# 接单评估：系统到底怎么算

> 对应当前代码（2026-11-04，尚未提交）。计算在 `web/shared/order-judge-quote.ts`、`order-judge-sheet.ts`，提示词在 `order-judge-brief.ts`

## 一句话

这里**没有训练模型**。AI 只负责把材料整理成清单，价格是固定公式算的，「学习」只是用你的历史记录统计出几个数。所以每个价格都能一步步算回去，出问题也查得到。

## 一单怎么走

```
材料 → AI 整理：每条需求的优先级、小时、这小时花在哪（确认 / 验证 / 接手 / 上线 / 直接做）、项目类型
     → 公式：粗算价格，可拖滑块、可填实际报价
     → 你保存、报价、成交、回填
     → 统计：下一单用到的 4 个数 + 行情
```

## 价格公式

```
每条金额 = 小时 × 时间值
底线 = 所有条目 + 兜底（商单里没说清的条目，多算 0.5 倍小时）+ 交付后修改 + 实际支出
报价 = 底线 ÷ 0.8，取整到 10 元（不足 ¥50 按 ¥50）
```

| 这小时花在哪 | 默认时间值 | 来源 |
|---|---|---|
| 直接做（界面叫「AI 直接写好」，其余四类分别叫「和客户对清楚需求」「先试能不能做成」「读懂旧系统再改」「上线前把关」） | 不计时 | 开发者：从 0 到 1 很廉价 |
| 学生单全部 | 67 | 一单真实成交：¥200 ÷ 3 小时，开发者觉得值；开发期基准，不进行情样本；校准值优先 |
| 确认、上线 | 31 | 答题，**开发者认为不可靠** |
| 验证、接手 | 267 | 答题，**开发者认为不可靠**；用在验证上是推断 |

三档按优先级切：基础 = 必须，推荐 = 加应该，完整 = 加可以。相邻两档价差不到 1 成就合并。填了实际报价，只报那一个价。

**这个价只是粗算。** 它反映不了市场，也从未被真实成交验证过。

## 系统会学什么

只用最近动过的 50 个项目。回填的东西各管各的，互不混：

| 你做的事 | 改什么 | 怎么算 |
|---|---|---|
| 拖滑块保存；或没拖就报出去（算认可） | 小时系数 | 显示的小时 ÷ AI 的小时，每个项目一个样本，攒够 3 个项目才生效，取中位数 |
| 做完填实际小时 | 小时系数（优先于上一行） | 实际 ÷ AI 的小时 |
| 做完选**亏**（做得痛苦、钱少了） | 时间值**往上抬** | 实际到手 ÷ 实际小时 = 这单每小时拿多少；时间值至少抬到所有「亏」的中位数 |
| 做完选**值** | 时间值**压住上限** | 时间值不高于所有「值」的中位数 |
| 做完选**刚好** | 时间值 | 所有「刚好」的中位数，再受上面两条约束 |
| 报价后选**我没接** | 时间值往上抬 | 视同这个价你不愿做 |
| 客户**嫌贵** | 攒够 3 单后时间值**往下压** | 客户说的预算（没说按报价）÷ 预计小时，取中位数当上限；和「亏」冲突时取中间。自用版还显示同类预算中位数 |
| 成交 | 行情 | 同项目类型 + 同客户类型，近一年攒够 3 单，显示中间一半的价格范围 |

小时系数和时间值都分两组：「新做」（确认、上线、直接做）和「接手改」（验证、接手）。

**你的感受确实算进去了**，但只有亏 / 刚好 / 值三档，不分痛苦程度。例子：收 ¥800、实际 10 小时、选亏 → 这单每小时 ¥80 → 新做时间值从 31 抬到 80，之后的粗算都按 80。

已报价、已成交的版本会冻结当时的数，之后学到的东西不改报出去的价。

## 可能「越用越坏」的地方

都是当前真实存在的问题，不是假设：

1. **嫌贵的单少时还压不住：** 不满 3 单嫌贵时，只有「亏」的话时间值仍然只升不降。
2. **嫌贵不分原因：** 客户可能只是习惯砍价，也一样算进去。
3. **系数起步慢：** 前 2 单不调整小时系数，AI 偏得再多也要等第 3 单。
4. **行情样本很小：** 3 单就显示，而且目前全是你自己的成交，只能说明你以前收多少，不代表市场。
5. **AI 分类决定价格：** 一条从「确认」变成「验证」，每小时差约 8.6 倍。AI 标错，价格就错，系统不会自己发现。
6. **没有准确度指标：** 系统目前算不出「估得准不准」，只能你看着判断。

## 出问题时怎么查

1. 点报价区下面的「系统目前学到了什么」：看现在的时间值、小时系数，依据几单。
2. 看自用版每条的算式：`8 小时 × 267 = ¥2,136`，错在小时还是时间值一眼能看出。
3. 只想知道样本：行情那一行写了几单。

判断规则：小时明显不对是 AI 或小时系数的问题；小时对、价格不对是时间值的问题；行情和粗算差很远，以行情为准。

## 滑块和样本的约束

- 行序、上限、是否收起只看 AI 原始估计，不看当前拖的值，否则拖动中行会换位、滑块会越拖越远
- 界面不再提供「不贡献」开关，成交、嫌贵、没回音默认进匿名样本；老版本存的 `share: false` 仍然不进。上线前隐私说明要写明这一点

## 校准按客户类型分开

商单、学生单、个人单、待确认各算各的，一个项目按最新版本的客户类型归组，「最近 50 个项目」也是每类各算。各类从自己的起点出发：学生单 67，其余 31 / 267。

## 越用越准

- **传给 AI：** 整理需求时附上同客户类型最近的条目记录（当时估的 → 最后的），改动过的在前，最多 30 条，估 0 的也算。发给 AI 的是自己账号的历史条目标题
- **分类系数：** 确认、验证、接手、上线各算各的，满 3 单生效，优先于新做 / 接手改两个总系数
- **不会重复修正：** 系数比较的是 AI 当时的输出，AI 学到经验后比值趋近 1，系数跟着回落，只剩没学到的那部分偏差
- **准确度：** 「系统目前学到了什么」显示 AI 估的小时和实际的平均差、成交率
- **没验证：** 真实 AI 是否真的按经验估，要等真实单子
- **相似度先不做：** 现在只按最近和改动过挑 30 条。超过 30 条时「系统目前学到了什么」会自动提醒；提醒出现且 AI 偏差不再缩小，才值得做
