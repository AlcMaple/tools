# 移动端导航栏「钉住不跳」—— 通用实现指南

顶栏 / 底部标签栏在手机上随页面滚动上下抖、底部内容被一条空白带盖住 —— 同一个病根：
**页面滚动挂在根文档上，而手机浏览器的可视高度是会变的。**

本项目（`anime.alcmaple.cn`）已按此实现：

- SPA 壳：[`web/src/index.css`](../../web/src/index.css)（§2 那段 media query）+ [`web/src/App.tsx`](../../web/src/App.tsx)（`sheetRef` 路由重置）
- 裸页面（服务端拼的播放页，不走 React）：[`web/server/xifan.ts`](../../web/server/xifan.ts) 的 `PLAY_PAGE` 样式块

这份文档怎么用：

- **本项目又出现** —— 只看 §1 分诊，落到哪类，对应实现已经在了，直接按 §5 验收。
- **另一个项目 / 另一台机器** —— §2 §3 是**可以整段照抄的骨架**；§4 是**每个项目必须自己填的量**
  （选择器、断点、栏高），照 §4 的流程逐项量出来再填；§5 是验收；§6 是踩过的坑。
- **只想确认是不是这个病** —— 只看 §0 §1。

适用范围：任何手机端有固定顶栏 / 底栏的网页，SPA 与多页 / 服务端渲染都适用，与框架无关。

---

## §0 症状形状

```
手机浏览器（iOS Chrome / Safari / Android 各家内核）
  ├─ 往下滑 ──► 顶栏跟着漂 / 底部标签栏被地址栏顶上来又落下去
  ├─ 滑到底 ──► 最后一块内容被一条纯背景色的空白带盖住，怎么滑都露不出来
  └─ 切走再切回 / 进出全屏 ──► 空白带宽度变了，或者短暂恢复正常

桌面浏览器把窗口拉窄 → 完全复现不出来   ← 关键线索
```

复现不出来是因为桌面没有**会收放的浏览器工具栏**：手机上地址栏、底部工具栏随滚动伸缩，
`100vh`、`height:100%`、`innerHeight`、`dvh`、`lvh` 在同一时刻能给出**四个不同的数**。

---

## §1 分诊（先做，别直接改 CSS）

在真机上打开页面，用远程调试或页面内埋一次性探针，取这四个数：

```js
[document.documentElement.clientHeight,      // height:100% 的基准
 window.innerHeight,                          // = visualViewport.height，工具栏占位后的可视高
 window.visualViewport.height,
 CSS.supports('height','100lvh')]             // lvh = 工具栏收起时的最大绘制高
```

再补一发命中测试，确认那条空白带底下到底是什么：

```js
['minus2px','minus40px','minus120px'].map((k,i)=>{
  const y = innerHeight - [2,40,120][i]
  const el = document.elementFromPoint(innerWidth/2, y)
  return k + '=' + (el && (el.className || el.tagName))
})
```

| 现象 | 病名 | 去 |
| --- | --- | --- |
| 顶/底栏随滚动位移，四个高度值基本一致 | 根文档滚动 | §2 或 §3 |
| 命中测试打到页面内容（不是遮挡元素），但屏幕底部一块是背景色 | **高度基准取矮了**：按 `innerHeight` 布局，实际绘制区是 `lvh` | §3 |
| 命中测试打到某个 `position:fixed` 元素 | 真的有东西盖住 | 查那个元素的 z-index / 高度，本文不覆盖 |
| 底部内容被系统手势条压住 | 安全区没留 | §4 第 5 项 |

> **本项目实测**：iOS Chrome 152 / iOS 26，`innerHeight` 与 `visualViewport.height` 都稳定报 **684**，
> 而 WKWebView 真正绘制的区域是 **874**（`100lvh`）。按 684 布局时，屏幕最下面那 190px 画的是
> html 背景，滚动框够不到 —— 看上去就是「底部被空白盖住」。命中测试全程打在内容上，
> **没有任何元素在遮挡**，这一条把「找遮挡元素」的方向整个否掉了。

## §2 照抄：SPA 外壳（React / Vue / 任意单页）

思路一句话：**根节点钉死在视口，页面滚动下放给内容容器**。顶栏和底栏于是永远跟视口对齐，
不参与滚动，自然不会跳。

```css
@media (max-width: 960px) {          /* 断点见 §4-1 */
  html,
  body {
    width: 100%;
    height: 100%;
    min-height: 0;                   /* 抵消常见的 body{min-height:100vh} */
    overflow: hidden;                /* 根文档不再滚动 */
  }

  body { position: fixed; inset: 0; } /* iOS 上还得钉一次，否则橡皮筋会拖动整页 */

  #root {                            /* 挂载点见 §4-2 */
    position: fixed;
    inset: 0;
    width: 100%;
    height: 100%;
    display: flex;
    flex-direction: column;
    overflow: hidden;
  }

  #root > .m-top   { flex: 0 0 54px; }        /* 顶栏：固定高，见 §4-3 */
  #root > .shell   { flex: 1 1 auto; min-height: 0; height: auto; overflow: hidden; }
  #root > .shell > .sheet {                    /* 唯一的滚动容器 */
    height: 100%;
    min-height: 0;
    overflow-y: auto;
    overscroll-behavior-y: contain;            /* 滚到底不把手势传给外层 */
    -webkit-overflow-scrolling: touch;
  }
}
```

配套的 JS 只有一处，**不能省**：路由切换时的"回到页首"要滚**这个容器**，
根文档已经不滚了，`window.scrollTo(0,0)` 变成空操作。

```tsx
const sheetRef = useRef<HTMLElement>(null)
useEffect(() => {
  window.scrollTo(0, 0)                                         // 保留，桌面端仍需要
  sheetRef.current?.scrollTo({ top: 0, left: 0, behavior: 'auto' })
}, [route])
// ...
<main ref={sheetRef} className="sheet">…</main>
```

底部标签栏保持 `position: fixed; bottom: 0`，并在滚动容器上留出等高的下内边距
（本项目 `.sheet { padding-bottom: 110px }`）。

## §3 照抄：裸页面 / 多页应用（没有统一挂载点）

结构上少一层 `#root`，用 `body` 当定位父级，滚动框绝对定位撑满：

```css
@media (max-width: 960px) {
  html,
  body {
    width: 100%;
    height: 100%;
    height: 100lvh;      /* 关键：对齐"真正被绘制的区域"，不是 innerHeight */
    min-height: 0;
    overflow: hidden;
  }
  body { position: relative; }

  .page-scroll {         /* 唯一滚动容器 */
    position: absolute;
    inset: 0;            /* 高度只来自 body，不再单独写一个高度来源 */
    width: 100%;
    height: auto;
    min-height: 0;
    overflow-y: auto;
    overscroll-behavior-y: contain;
    -webkit-overflow-scrolling: touch;
  }

  .page-scroll > .content {
    min-height: 100%;
    /* 工具栏最多吃掉 lvh - svh 这一段，滚到底时留白让最后一行仍露在工具栏之上 */
    padding-bottom: calc(60px + env(safe-area-inset-bottom, 0px) + 100lvh - 100svh);
  }
}
```

两条**必须成对**的规矩，破一条就退回旧病：

1. **父子只能有一个高度来源。** `html/body` 用 `lvh`，子框就只用 `inset:0` 跟随。
   曾经只给子框写 `100dvh`、父框留 `height:100%` —— 子框比父框高 190px，
   被父框 `overflow:hidden` 裁掉，末尾内容直接消失。
2. **基准取 `lvh` 不取 `dvh`/`%`。** `dvh` 跟着工具栏动，动画期间父子不同步；
   `height:100%` 在 iOS Chrome 上取到的是那个偏矮的 684。取 `lvh` 换来的代价是
   工具栏展开时底部一段被挡住，用上面那条 `100lvh - 100svh` 的补偿留白抵消。

## §4 每个项目必须自己确定的量（不能照抄）

| # | 要素 | 怎么定 |
| --- | --- | --- |
| 1 | **断点** | 用项目里已有的「移动端布局」断点，**不要新造一个**。本项目 `max-width: 960px`。改这里等于同时改栏的显隐规则。 |
| 2 | **挂载点选择器** | React 常见 `#root`，Vue `#app`，Angular `app-root`，裸页面用 `body > .shell` 之类。`document.querySelector('#root')` 在真机确认一次。 |
| 3 | **顶栏高度** | 量当前顶栏的实际渲染高：`document.querySelector('.m-top').getBoundingClientRect().height`。填进 `flex: 0 0 <h>px`。**写死的这个数必须和顶栏自身 CSS 的 height 一致**，两处不同步就会露缝。 |
| 4 | **底栏高度 → 滚动容器的 padding-bottom** | 同上量底栏，再加 `env(safe-area-inset-bottom)`。本项目底栏 50px + 内边距，取 110px。宁可多留 10px。 |
| 5 | **安全区** | 有底部手势条 / 刘海的机型才需要。前提是 `<meta name="viewport" content="... viewport-fit=cover">`，否则 `env(safe-area-inset-*)` 恒为 0。 |
| 6 | **滚动容器的选择器与代码引用** | §2 的 JS 要拿到这个容器。SPA 用 ref；裸页面用 `document.querySelector`。**路由/页面切换的每个入口都要调**，漏一个就表现为"某个页面进去是半截"。 |
| 7 | **CSP** | 如果站点开了严格 `style-src`（无 `unsafe-inline`），所有样式必须落在带 nonce 的 `<style>` 或外链 CSS 里，**不能用内联 style 属性**动态改高度。本项目播放页正是这种情况，所以全部用静态 CSS + `lvh` 解决，一行 JS 改高度都没有。 |
| 8 | **既有的 `min-height: 100vh`** | 全局样式里几乎一定有一条 `body { min-height: 100vh }`。§2 §3 里的 `min-height: 0` 就是为了抵消它 —— 确认你项目里那条在哪、有没有更高优先级的变体。 |

---

## §5 拼装顺序与验收

顺序：先 §1 分诊 → 按 §4 量出 6 个数 → 贴 §2 或 §3 的 CSS → 补路由滚动重置 → 真机验收。

真机（不是桌面窄窗口）逐条过：

- [ ] 首次进入：顶栏、底栏在位，底部**没有**空白带
- [ ] 快速上下滑到底、到顶：两栏纹丝不动，橡皮筋不拖整页
- [ ] 滚到最底：最后一行内容完整露在底栏之上
- [ ] 切换路由 / 页面：新页面从顶部开始，不是半截
- [ ] 进出全屏（有视频的话）、切后台再回来、横竖屏各一次：空白带不出现
- [ ] 弹出软键盘（有输入框的话）：布局不塌
- [ ] 桌面端窄窗 ≠ 验收通过。**iOS Chrome 和 iOS Safari 要分别过一遍**，它们的高度上报不一样

## §6 坑（都是真踩过的）

- **`innerHeight` ≠ 绘制区。** iOS Chrome 上实测 684 vs 874。所有"按 innerHeight 算高度"的
  JS 方案在这台机器上都会留下 190px 空白带。
- **命中测试干净 ≠ 没问题。** 空白带底下就是内容本身，没有遮挡元素 —— 顺着"找遮挡元素"
  查会一路查空。分诊要看**高度数值**，不是看 DOM。
- **父子两个高度来源**是最容易复发的错。任何时候只允许一层定高，其余 `inset:0` / `100%` 跟随。
- **`window.scrollTo(0,0)` 静默失效。** 根文档不滚之后它不报错，只是什么也不做。
- **切 `overflow` 强制重排、延时刷新、`-webkit-fill-available`** 这几招在本项目全部无效，
  别再试；它们治的是"尺寸没更新"，而这里是"尺寸基准选错了"。
- **只有一个滚动容器。** 嵌套滚动框在 iOS 上会互相抢手势，表现成"滑不动"或"滑过头"。

---

## §7 一句话教训

先量高度，再改 CSS。这个 bug 前后返工四轮，都是因为跳过 §1 直接猜遮挡元素 ——
真正定案的是那三行探针打出来的 `684 / 874`。
