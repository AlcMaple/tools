# 接单评估三端同步

本地实现，尚未上线。Mac 网页、手机网页、Windows 网页及桌面共享模式使用同一网站账号的资料、评估服务和历史。

## 电脑上的文件说了算

- 服务器每个账号只存两份正文：能力档案、项目日志。不合并，不存候选稿、旧版本或合并基线，也就没有「冲突」要人处理。
- 路径列表也按账号存一份（每类最多 12 条），标明是哪台电脑加的。顺序就是优先级：每台电脑按顺序取**第一个本机存在的文件**，内容和服务器不同就整份覆盖；一个都不存在时不上传，直接用服务器上的那份（没有上传过文件的手机就是这种情况）。
- 桌面应用开启「与网页版共用评估和历史」时，本机路径**追加**到账号列表末尾，已有的保持原顺序；之后在桌面或网页里调顺序、移除，都改的是同一份列表。网页里看得到每条路径、来自哪台电脑，当前正文来自哪一条会描边标出。
- 撤销、删行和普通修改一样，保存后整份覆盖上去。两台电脑都在线且选中的文件不同时，最后上传的那份胜出。
- 找到的文件正在保存（两次读取大小 / 时间不同）、是空文件或超过 1 MB 时报错，不往下一个路径找，以免把别的旧稿当新稿传上去。
- 网页（含手机）「上传文件」也是列表里的一条，标为「网页」，正文存在服务器，任何设备都算存在；新上传的追加到末尾，同名再传替换内容。它排在电脑路径前面时立刻成为正文、电脑不再覆盖；排在后面时以电脑上的文件为准。

## AI 与开关

- 桌面应用不再自己填 API Key、不再直连模型。评估一律走网站，AI 跟随网页账号设置：默认用服务器 AI；网页设置里改成自己的 key 时用用户的（key 只在那台浏览器里，需要先在网页连接一次）。
- 桌面只有一个开关「与网页版共用评估和历史」。未登录网页版账号时打开会提示先登录；未开启时不能评估，只能查看旧的本机历史。
- 开启时本机旧历史自动上传一次（先备份并校验，原记录不删，重复上传去重）；共享历史满 50 条或单条超过 20 MB 时停下并提示，开关保持开启。

## 一次配置

1. Mac、Windows 各自在应用设置登录同一网页版账号。
2. 评估设置里给每类资料添加本机路径，打开「与网页版共用评估和历史」。
3. 在任一端（桌面或网页）调整路径顺序。
4. 根目录构建后，`npm run sync:judge` 以无窗口模式运行。停止组件后不会继续同步。本次没有安装开机启动项。

组件只读、发布选定源文件，不修改原 MD，不读取其他文档；本站不反写这份日志。旧版设置里的单个路径、`profilePaths` / `logPaths` 会自动转成新格式，旧的 DeepSeek Key 不再使用。

## 本地服务目标

先启动一个仅监听回环地址的网页开发服务，例如：

```sh
cd web
npm run dev -- --host 127.0.0.1 --port 18740
```

桌面配置和后台启动都使用同一个目标，防止误连线上：

```sh
# 在仓库根目录执行
MAPLETOOLS_WEB_URL=http://127.0.0.1:18740 npm run dev
# 完成配置并结束开发进程后：
npm run build
MAPLETOOLS_WEB_URL=http://127.0.0.1:18740 npm run sync:judge
```

更换目标必须重新确认网站账号。开发验收可以另设 `MAPLETOOLS_TEST_USER_DATA` 为专用绝对目录，避免碰现有应用数据；该隔离入口只在未打包时生效。

## 更新与评估

保存后通过父目录原生事件合并触发定点读取，兼容原子替换与 CRLF。启动、唤醒、重新建立连接、评估屏障再核对，不做周期文件扫描。

服务端通过事件流向在线源发出一次核对，等待其完成发布，再一次固定两份资料版本。来源核对失败或超时均在调用 AI 前结束。资料在模型运行中更新只影响下一次评估。

网页 / 桌面收到变更通知后读取权威状态；网页从后台恢复后重新连接，不依赖手机长期保活。来源离线时保留服务器最后确认的版本；未发布的离线修改不属于已同步资料，不承诺跨端零延迟。

HTTP 401、429、5xx 不自动重试。传输中断最多两次有界重连；若仍失败，手动「立即同步」或重启组件。新文件事件可解除文件正在保存、暂时缺失等源读取错误，但不会触发 HTTP 错误重试。

## 历史与备份

共享模式中的文字、处理后图片、结论与资料版本保存在网站。开启共用时原本的本机历史自动上传一次：

- 先备份原 JSON、图片并校验，再逐条导入；原记录不删除。
- 重复导入不新增记录，已在共享端删除的旧记录不被重新导入复活。
- 单条超过 20 MB 或共享历史已达 50 条时停止，并保留原件、备份和已经完成的迁移；不静默裁剪。

原网站 ZIP 备份已包含接单评估两份正文、路径列表、历史与图片；旧备份里的版本、候选稿表在恢复时忽略。已有资料的账号导入时保留当前接单评估数据；空目标可完整恢复。恢复失败时新图片跟随数据库事务回滚。Markdown 备份仍是原追番阅读稿，不充当接单评估可恢复备份。

## 回归命令

```sh
cd web
npm run test:order-judge
npm run test:order-judge-mutations
npm run test:backup
npm run test:order-judge-background
```

后台回归需先在根目录执行 `npm run build`。它会启动真实 Electron 与临时回环 HTTP 服务，使用临时文件、SQLite 和账号；AI 边界为替身，退出时清理全部进程及数据。

可选真实浏览器验收：设置 `JUDGE_BROWSER_MODULE` 指向已安装的 Playwright 模块，`JUDGE_CHROME_BIN` 指向 Chrome 可执行文件，再运行后台回归。它额外验证电脑 / 手机尺寸网页设置页没有冲突入口、以电脑文件为准的评估；这不等于 Windows 操作系统、iPhone 真机或百度客户端实测。
