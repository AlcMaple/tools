# Web Agent 功能说明

本文随 Web 功能代码维护，供后续服务器功能知识清单接入使用。**阶段 6 接入外部 AI 与访客临时对话；有 key 默认开放发送，页面后台完成真实连接探测后回答。六个登录只读工具、三个访客公开工具均不执行追番写入或播放。** 实际可用能力仍以服务器正在运行的代码、开关和账号权限为准。

## agent.history：个人会话历史

**用途**：保存自己的 Agent 会话，换一个已登录客户端仍可读取已经保存的内容。

- 新对话先保留在当前界面；首次发送才写入历史。支持列表、重命名、逐条归档、恢复、清空、删除和 JSON 导出。
- 首条消息按内容提取简短标题，仅生成一次；手动改名优先，后续消息和清空后的续聊不再自动改名。
- 保存用户消息、助手已生成正文、来源卡片、工具摘要和动作状态；部分回复也可保留。
- 会话默认私有，不进入公开追番大厅；仅当前登录账号读取和管理。
- 两端同时修改时先检查版本，旧请求提示刷新，不覆盖较新的内容；重复发送同一次创建/消息请求不重复保存。
- 归档后保留阅读和导出，恢复后再继续追加；进行中的回复或待完成动作须先结束或取消，再清空、删除或归档。
- 清空会移除本会话内容，但保留会话名称和当前番剧；删除移除整本会话。操作前先导出要保留的记录。
- 导出仅包含已保存的可见内容与摘要，不包含应用凭据、系统提示词或原始模型/工具协议包。用户自行输入的正文会原样保存，请勿在聊天中粘贴密钥。

**当前入口与能力映射**：

| 项目 | 当前状态 |
|---|---|
| 会话管理 | `/api/agent/sessions` 服务端接口已实现 |
| 用户消息保存 | 会话下的 `messages` 接口已实现，只接收用户正文 |
| 助手正文 / 来源 / 动作摘要 | 仅供服务端写入，不开放浏览器伪造接口 |
| 右下角聊天入口 / 历史列表界面 | PC / 平板悬浮手帐已接入 |
| 上下文压缩 / 偏好 | 阶段 2 服务接口与适配器已实现，见下文 |
| 普通模型回答 | 已连接模型执行；追番写入和播放仍未开放 |
| Agent 模型工具 | 会话管理由应用处理，不新增模型执行权限 |

**容量与频率**：单账号最多 200 本会话、每本最多 10,000 条消息；正文及摘要合计每本 10 MiB、每账号 50 MiB。单条正文最多 32,000 字符，请求最多 128 KiB。读取 120 次/分钟、写入 30 次/分钟、导出 2 次/分钟，达到限制保留既有内容。

修改本功能时同步更新用途、入口、限制和实现状态；尚未部署的变更不提前描述为线上可用。

## agent.context：上下文压缩与确认偏好

**用途**：整理下一轮需要发送的上下文，保留完整聊天原文；用户确认的偏好可跨会话使用。

- 支持手动 `/compact`、压缩状态查看与取消；准备下一轮上下文时达到有效窗口的 78% 可启动同一压缩流程。回答循环已复用该准备入口。
- 默认保留最近 10 轮、用户固定的原文、未完成动作及尚未回应的用户消息；可按关键词或已有来源/动作编号回填旧原文。
- 摘要生成先抽取、独立核验，再分层合并；缺失锚点回填后再次检查。失败、取消、预算不足或资料变动时，旧活跃摘要保持不变。
- 摘要可查看、编辑并恢复旧版；编辑/恢复都产生新版本，不删除聊天。原生 opaque 状态只供服务端续传，不作为聊天或导出内容。
- 偏好固定为说话方式、喜欢的标签、避开的类型和推荐重点四项，每类一个值。切换分类分别编辑，一次保存四项；保存即为本人确认，留空表示默认。清空或删除某段会话不影响这些账号设置。
- 有效窗口取所选档位和模型上限中较小值。默认自适应，固定内容确实需要更多空间时才扩档；用户明确固定档位后不自动突破。

**当前入口与能力映射**：

| 项目 | 当前状态 |
|---|---|
| 上下文准备 / 手动压缩 | 会话下的 `context/prepare`、`compact` 接口；精确 `/compact` 命令可转入压缩任务 |
| 摘要版本 / 原文固定 / 偏好 | 会话下的 `summaries`、消息 `pin` 及账号级 `preferences` 接口 |
| 默认服务器模型联调 | 需要维护者显式开启；没有自动 fake 或免费模型替代 |
| OpenAI / Claude 原生适配、DeepSeek 应用摘要 | 适配器与受控响应测试已完成；真实模型质量仍需后续验收 |
| BYOK 配置和连接入口 | AI 页选择核准端点 / 型号并填写临时 key，探测通过后供回答和压缩共用；失败不切换 |
| 偏好卡、压缩按钮及浮层状态展示 | PC / 平板悬浮手帐已接入，实际压缩仍取决于模型配置 |

每个账号同时只进行一次压缩，最长 10 分钟；单任务最多 48 次模型操作，并有按窗口计算的 token 预留上限。每本会话保留最近 30 个摘要版本、100 条压缩记录；当前设置最多四项，每类一个值；旧卡片数据读取时按分类取最近确认值，保存时合并，不由读取操作删除原记录。完整聊天历史不因压缩而裁掉。

## agent.run：只读运行循环与进度恢复

**用途**：服务端按轮准备上下文、校验模型请求与只读结果，保存进度；断开聊天连接不等于取消任务。

- 同账号同时只运行一轮。每轮最多 12 轮工具调用、每轮工具请求最多 4 个；已注册六个本地只读数据工具；服务器 AI / BYOK 均受相同权限和额度限制。
- 正文片段、来源、工具摘要与用量通过校验后落入账号历史；模型的额外工具、身份字段、伪造来源、写入或播放请求不会执行。正文只作为文本数据展示。
- 3 分钟提示较慢、8 分钟标记长任务、10 分钟保存为可继续状态；累计 30 分钟后要求新回合。用户取消保留已生成片段，旧响应不覆盖终态。
- 查询超时单独记录；模型和工具请求不由传输层自动重试。SSE 的 15 秒 heartbeat 与模型进展分开，60 秒无进展会暂停；订阅断开后可按事件序号恢复，客户端最多重连 2 次，HTTP 错误不重试。
- 回合列表供另一端重新找到活动或暂停记录。恢复需要用户请求和当前会话 revision；有更新的用户问题时，旧回合停止恢复，避免回复错位。
- 每轮开始和恢复时装配服务器功能快照；下一次模型/工具调用及结果接收前再次检查版本和账号权限，变更后暂停旧回合，待用户明确继续。
- 代码与功能说明在构建时生成共同指纹，服务启动后固定为本次运行快照。只更新仓库或磁盘不会替换运行中的版本；代码和说明不匹配时标记待同步，不引用其他版本补造功能。
- 当前快照覆盖已登记 Web 功能与六个只读工具；邮箱、Google、福利等按运行配置及账号资格过滤。模型对实际功能的理解仍需后续真实评测。

**当前入口与能力映射**：

| 项目 | 当前状态 |
|---|---|
| 功能快照 | 登录后 `GET /api/agent/knowledge`；按运行版本、开关和账号能力生成 |
| 创建 / 列表 | `POST / GET /api/agent/sessions/:sessionId/runs`；列表使用时间和 ID 双游标 |
| 回合状态 / 进度 | `GET /api/agent/runs/:runId` 及其 `events` 接口；只返回可见元数据 |
| 用户取消 / 恢复 | 回合下的 `cancel`、`resume`；不因连接重建重放模型调用 |
| 真实回答模型 / 数据工具 | 六个只读工具与账号会话绑定；真实 JSON / 工具探测成功才标记模型就绪，生产没有 fake 代答 |
| 浮层及刷新按钮 | 已接入；已显示旧页面提示，保留草稿并由用户点击刷新 |

每会话最多保存 100 个回合，每回合最多 2,048 条事件及 256 KiB 内部检查点；事件与检查点合计每回合 2 MiB、每账号 10 MiB，并参与历史总空间检查。每账号最多 2 条 SSE 订阅。清空/删除会话会清理其回合和事件，独立确认的偏好保持原有语义。

## agent.chat：纱雾助手

**用途**：在当前页面旁打开一页小手帐，查看历史、来源与进度；收起不会取消已开始的回合。

- PC / 平板右下角 52px 纯头像入口，面板约 440px 宽并按可视区域收缩；独立固定浮层，不挤占主内容，平板避开底部导航。手机入口和卡片按钮隐藏。
- 会话列表支持切换、分页、新建、重命名、归档、清空、删除和导出；清空/删除有独立确认，不把收起解释为取消或删除。
- 助手正文支持 Markdown 标题、粗斜体、引用、列表、表格、任务清单、链接与带复制按钮的代码块；用户消息仍按原文展示。来源卡、工具摘要与动作状态分别呈现。追番变更预览卡可确认或取消（阶段 7）；播放动作仍在阶段 8。
- 自己发的消息上有「编辑」按钮：点击把该条放回输入框，发送时**截断这条之后的所有对话**再重新回答（类似传统 agent 的编辑重发，不做多分支保留）。截断作废该会话的摘要与上下文任务，当前番剧和已确认偏好不动。会话有进行中的回复或待确认动作时不能编辑。
- 纱雾可以用**自身的动漫知识**识别用户说的作品（名字不精确也行）、解释剧情设定、按画面或情节推断是哪部番的第几集、比较作品——这类内容会标明是它的判断、可能有误。但**项目专属数据**（当前账号的追番状态/进度/标签、周历缓存、公开点评与统计）只来自工具，工具没返回就直说没有，不靠记忆或推断编造。纱雾没有联网工具。识别出的番若不在离线索引里，用户确认标题后可用「自己记一条」加进追番（服务端建自定义条目，见阶段 7）。
- 主输入保留未发送草稿，支持建议问题、Enter 发送、Shift + Enter 换行和输入法组合状态；会话草稿分别保存于当前账号的内存，退出账号清理。接口归属不匹配时不读取返回正文；跨标签页账号变化会先清理旧界面，再向服务器确认身份。
- SSE 支持进度、部分正文、未读、取消、暂停恢复和断线后重新读取；终态先回读权威消息与 revision，再开放依赖新版本的操作。
- 压缩按钮、`/compact`、任务状态/取消、上下文档位、摘要版本查看/恢复及四项偏好设置已接入；模型不可用时说明状态并保留原文，不显示假回复。
- 周历、我的追番、公开卡片及详情可通过按钮带入当前番剧；chip 可清除或通过另一张卡片切换。带入已在页面上的 ID / 标题和已知年份、集数、标签；未提供字段保留未知，不为按钮额外请求在线资料。
- 找番失败时可由用户打开原有普通搜索；点评/片源入口按已知上下文与资格展示，目标追番页再次校验。没有模型自动导航、发布、解析或播放。
- 旧页面提示仅要求用户点击刷新；有草稿时先提示收好，不擅自重载。开屏就绪通知与首次公告分开，刷新、跳过开屏及减少动画设置不隐藏入口。

**当前可测试内容**：配置好 key 后直接发送，再验收真实回答、来源、费用、取消及上下文；连接失败时保留输入。访客仅显示临时聊天、来源、停止和登录入口，不显示个人管理能力。

### 阶段 4 实机反馈修订（2026-09-08）

- 头像复用原图集的顶部正面区域，仅显示单张脸；入口不再带标题、副标题或展开箭头，运行及未读状态浮在头像边缘。
- 对话、历史、新建、偏好及设置入口保持一致；短视口保留导航，通过顶栏“对话”直接返回，不另设重复返回按钮。设置只管理当前会话，不重复顶栏或常驻刷新按钮；未发送的对话不显示归档入口。
- 偏好用于后续回答和推荐：四类分别输入，点击“保存”一次提交；空白为默认。没有添加列表、待确认卡或管理员审核，分类切换保留各自内容。
- 删除装饰性说明与备忘录式文案；上下文入口直称“上下文”，整理动作称“压缩上下文”。真正版本过期时仍显示更新提醒，刷新草稿须显式确认。

- 保存偏好通过 `PUT /api/agent/preferences/settings` 原子替换四项，按账号版本检测冲突；失败不部分保存。旧卡片接口保留兼容但拒绝重复分类。
- 历史列表在服务端过滤从未发送的空会话（不删除旧数据），每项提供独立归档/恢复入口。

## 阶段 5：本地数据与功能知识

六个工具只在服务器白名单中执行，无模型可调用的任意 URL、SQL、shell、截图或文件接口；未新增绕过运行循环的公开工具执行 HTTP 端点。真实回答仍在阶段 6，当前通过 `npm run test:agent-data` 验收。

| 工具 | 实际来源与边界 |
|---|---|
| searchOfflineAnime | 本机只读 BGM 索引及本地补充表；标题/别名子串、精确标签、年份、集数和标签相似筛选，筛选后排序截断。生产索引缺失即 CACHE_MISS、不在线兜底；仅本地开发（非生产）且无索引时，复用页面搜索同款「借线上离线结果」兜底并写入本地补充表（见阶段 7 说明），不请求 BGM。未知集数不匹配集数上限，完结条件返回 CONTEXT_MISSING，不按年份或集数猜测。 |
| readCurrentAnimeContext | 只读当前账号、当前会话由页面按钮带入的结构化快照。载荷与番剧 ID 必须一致，切换 ID 清除旧载荷；文字视为不可信资料，不变成指令或权限。未提供简介不自动读取详情。 |
| readCachedCalendar | 只读现有内存/磁盘周历缓存，按星期筛选；缺失明确报错、14 天过期照实标记，不触发刷新。 |
| listMyTracks | 当前账号的动画追番、进度、状态、用户标签与 tracks_rev；不返回 extra、凭据、封面路径或另一个账号的数据，也不触发资料补全。 |
| listPublicReviews | 同时满足作者公开开关、已发布、对应作者动画追番仍存在；按番剧、模式、剧透上限筛选。不读取草稿或问题答案。 |
| aggregatePublicData | 预定义公开用户、动画追番、点评、推荐计数；可按番剧和状态过滤。未过滤的公开用户数包含开启公开但没有动画条目的用户；内容统计只计仍关联公开动画追番的发布内容。 |

- 查询有参数、数量、时间、身份和输出合同校验；来源携带读取时间。缺失字段不猜测，数据损坏给明确错误。公开开关或发布状态变化后下一次查询重新检查。
- 页面快照随会话 revision 更新，字节计入历史额度；清空会话同时清除该快照，保留当前番剧 ID。只读工具本身不写库或网络；用户点击带入资料属于已有会话更新操作。
- 访客仅准备周历缓存、公开点评和公开聚合三个工具及公开功能知识合同；离线搜索、私人追番和持久会话不授予访客。此阶段没有开放访客聊天路由或真实模型。
- 代码、功能登记、已审查路由清单及功能说明一起维护。新增路由、删除入口或说明漂移会阻断构建；维护者核对业务语义后运行 `npm run sync:agent-guide` 同步说明段和路由清单，构建不自动掩盖遗漏。
- 构建输出 `server/agent-guide.json` 与发布指纹；运行时核对代码和说明产物。部署应包含本次构建的 server 产物，缺失或损坏时知识状态为待同步。磁盘更新不替代进程已经加载的版本；语义是否准确仍由开发验收确认。

## 阶段 6：外部 AI 与访客运行控制

### 连接与凭据

- 配置好 `AI_API_KEY` 后，正常 `npm run dev` 即可。服务器有 key 默认开放输入发送；页面加载后在后台完成随机 nonce JSON + 工具调用探测，连接进度不进入对话。页面准备与发送复用同一个任务，连接复用 30 分钟，过期后按需再检查；失败保留草稿，由用户手动重试，没有周期性重试。首次打开页面的探测可能计费，仍经过原有配额与费用预留；多页面共享服务端正在进行的准备，近期失败短暂缓存，避免刷新制造请求突发。管理员可用 `AGENT_AI_ENABLED=0` 显式关闭所有 Agent AI；有 key 不等于连接已验证，`answerModelReady` 仍只代表探测成功。
- 默认型号 `deepseek-v4-flash-vision-exp`；官方 2026-09-08 列出 1M 上下文、JSON 和工具能力。费用按 USD 峰时上界估算：输入未命中 0.44、命中 0.014、输出 1.32 / 百万 token；不是供应商账单。来源：[DeepSeek 型号与价格](https://api-docs.deepseek.com/quick_start/pricing/)。扩展型号须核对价格卡；服务器升级还须 `AGENT_MODEL_APPROVAL` 中的基线失败记录和更强型号审批，不接受仅改型号。
- 登录用户可选服务器或 BYOK，现阶段生产入口开放 **Chat Completions 兼容端点**。已有 Responses / Anthropic 原生压缩适配继续保留并回归，但未开放这些协议的生产连接；当前连接使用同模型应用摘要，不把原生适配脚本测试当成生产能力。
- BYOK 默认仅核准 DeepSeek 基线。维护者通过 `AGENT_BYOK_PROFILES` 扩展精确 endpoint + model + 已核对窗口 / USD 价格；HTTPS、端口、凭据 URL、查询、片段、DNS 公网检查、地址固定和禁重定向共同约束，用户 endpoint 不成为任意内网代理。
- API key 只在表单与服务端临时连接内存中使用，发送后清空输入；不保存到浏览器持久存储、用户配置、历史、日志或返回体。服务端在过期、退出或账号撤销后移除；用户来源/endpoint/model 可保存在已有账号设置。BYOK 连接失败仍维持 BYOK 来源，不使用旧服务器连接代答。
- 本地网络层自动兼容固定 `api.deepseek.com` 的 198.18/15 Fake-IP，无需额外启动参数，TLS 仍验证原域名；生产/Vercel 与其他端点仍要求公网 DNS。未改系统 DNS 或代理设置，也没有放宽任意 BYOK URL 的权限。

### 额度与失败行为

```text
身份 / 参数 / 功能版本 → 持久单账号或 IP 预算 + 全局租约
  → 按实际请求字节与最大输出预留费用 → 真实模型流
  → usage 结算 / 未知费用保留预留 → JSON、来源、工具再校验
  → 登录账号写入既有历史；访客仅返回当前请求
```

- 保守默认值可通过 `AGENT_LIMITS_JSON` 修改，启用前由维护者确认：全站项目 AI 每日 US$1；账号每日 US$0.10 / 30 轮；访客每 IP 每日 US$0.02 / 10 轮；单轮 US$0.03（访客 US$0.01）；单次请求估算达到 US$0.005 预警；全局并发 2；单轮累计 256,000 token、每日 1,000,000 token。探测与手动压缩也消耗额度。BYOK 共用并发、token、账号限制，但不占项目支付的全局费用预算。
- 调用前事务预留，压缩子调用与回答共用本轮账本；费用、token、轮数和租约存放在 Web 既有 DATA_DIR 的 SQLite 中，无访客正文。未知 usage / 取消 / 传输失败不退回未知费用的预留；页面显示估算，不冒充实际账单。
- 每个账号或访客 IP 同时一个任务，跨连接并发受同一持久租约控制。预算以 UTC 日为单位；刷新、更换 requestId 或重启服务不清除当日额度。跨 UTC 日的长回合停止，不混算两日。
- 生产回答使用上游 SSE，每段到达即更新 Markdown；解析不依赖 JSON 字段顺序，首段立即下发，不拿完整文本模拟打字；最终 JSON 或来源校验失败保留失败片段，不标记成功。HTTP 4xx/5xx、无效格式不重试；原有登录 SSE 最多两次重连只读事件，不重放付费调用。
- `AGENT_ANSWER_OUTPUT_TOKENS` 默认 8192，可配置 256～8192；访客取较小值且最高 2048。上下文档位仍为 64k / 128k / 256k / 1m，但档位不是费用豁免，较长上下文可能先触及额度而被拒；不偷偷截断历史或降档。
- 访客单条 2000 字符，至多带回 12 条消息且总计 12,000 字符；单请求上下文上限 32k、正文 6000 字符、4 轮工具循环、120 秒。超限要求新对话，不静默裁剪。临时请求断开即取消，无自动重连；重复 requestId 只返回已用错误，不再次调用模型。
- 访客 IP 默认来自 socket，对任意转发头不信任。只有 loopback node + nginx 覆写 `X-Real-IP` 的部署才配置 `AGENT_TRUST_LOOPBACK_PROXY=1`；配置缺失时反代用户共享保守限额，不放宽身份边界。

### 回复呈现

- 页面预连接保持安静；发送立即出现自己的消息与纱雾的回复占位，在首字到达前也可看到动态等待状态。
- 文案跟随真实事件：整理思路、翻周历、查离线资料、读取自己的追番、查看公开点评或聚合公开数据。不会把本地缓存查询伪装成联网搜索，不显示模型私有思维过程。
- Markdown 用 React 元素渲染而非注入 HTML。原始 HTML 作为字面量转义，危险链接不激活，图片不自动下载；代码块只展示和复制、不执行。长代码与表格在消息内横向滚动。
- 流式生成途中可渲染未闭合的代码围栏；正文收到的片段立即显示，不添加人为打字延迟。上游最终格式/来源不合格时仍标记失败并保留已收到片段。
- 访客输入框下方不再显示刷新说明；刷新清空的行为不变。收起继续，身份变化或页面关闭时中止旧请求。

### 统计来源明细

- 公开统计在一条回复内合并为“来源：追番大厅 · N 项统计”，默认折叠；点击展开显示指标、数值、筛选、统计口径与查询时间。“查看大厅”是独立站内入口，点击才导航并收起助手，再打开仍保留对话；收起/展开来源不会联网查询。
- 明细由服务端查询直接生成，随来源保存和导出；查询值已在工具结果中，界面专用来源明细不会在回答请求中重复附送；模型仅能引用已知来源 ID，不生成来源的数值、口径或任意跳转 URL。结果验证核对明细与查询数据、参数一致。
- 公开用户无筛选时统计所有开启公开追番的账号，包括暂无动画追番的账号；带筛选时按符合动画记录条件的账号去重。公开追番按记录数计算，不是去重番剧数；点评/推荐仅计公开账号已发布且仍关联动画追番的记录。
- 同一指标、筛选、数值与口径的重复查询合并展示并保留来源和时间；不同指标、筛选或数值不会因为标签相同而被删除。不同时间的变化值分别保留，不冒充当前实时值。
- 旧记录只有来源标签/时间时，也合并为一个可展开组，但提示明细缺失，不从正文推断数值或补造口径。统计语义没有因这次展示修复而更改。

### 访客交互与验收

1. 在受保护配置填写 key、核对额度，正常启动 Web；打开头像直接发送，问“这个网站怎么用”“本周有哪些番更新”。检查公开来源，缓存缺失不自动补抓。
2. 收起再打开，对话保留；刷新后为空。访客没有历史、归档、偏好、固定消息、摘要或 BYOK 入口。两个标签页正文独立，刷新不重置服务端 IP 额度。
3. 提问“我的追番是什么”“把这部加入追番”“直接播放”，确认只解释登录后流程，不执行私人查询、写入或播放；直接伪造身份/工具参数同样被拦截。
4. 登录/退出/换账号后旧界面、草稿和请求清理，访客正文不迁入账号；运行中点击停止，已到正文保留，迟到片段不继续追加。
5. 登录后直接发送以使用服务器模型，或在 AI 页配置核准 BYOK；错误 key、未核准 endpoint、能力不足应明确失败。检查 token/费用、上下文档位、取消、额度预警和硬停；默认不升级型号。

## 阶段 7：追番变更确认与执行

登录账号新增一个 `proposeTrackChange` 预览工具与一条独立的确认执行链路。**模型只能生成预览；写入、旧值、revision、确认凭证都由服务端掌握，聊天文字、摘要、页面资料都不是确认或权限来源。**

### 预览

- 模型对当前账号的某部番调用 `proposeTrackChange`，给出 `add`（离线已收录的正数条目）、`update`（含自建负数条目）或 `add_custom`（**自己记一条**：离线库没有这部番时，模型给用户确认过的标题，服务端分配负 bgmId，等价页面「自己记一条」；不需要 bgmId、不联网），以及 `status` / `episode` / `userTags` 里的字段。
- 服务端按服务端会话固定账号身份，读取当前追番记录与账号 `tracks_rev`，算出改前 / 改后对照和一句影响说明，写入一条权威回执（状态 `prepared`，24 小时过期），并给消息附一张待确认动作卡。回执带一枚随机确认凭证，**只随回执存库，从不进入模型上下文**。TTL 只防长期悬挂；预览与确认之间的串改由 `apply` 的 `revision` 校验兜住。
- 动作卡展示改前 / 改后时，空标签直接省略（标签由用户打开「我的追番」页面时回填，不代表 Agent 拿不到）。用户可以不点确认 / 取消继续追问，或取消后再让纱雾改。
- 预览不写任何追番数据。`add` 的标题依次取自离线索引、本地补充表（`bgm_search_additions`，含用户从在线搜索加过的条目 / dev 借用的条目）、当前会话主动带入的页面资料；三者都没有才返回 `NOT_FOUND`，**不联网补全**。`update` 目标不存在、`add` 目标已在追番里、字段非法都直接返回错误，不生成回执。
- dev 环境本机没有离线索引（`bgm_index.db`）时，`searchOfflineAnime` 复用页面搜索同款「localhost + 非生产借线上离线结果」的兜底，把候选写入 `bgm_search_additions` 后再检索；生产有索引，永不走这条路径。
- 会话在有 `prepared` 动作时保持忙碌，期间不接受新回合、压缩或归档。

### 确认与执行

- 前端凭 owner 身份从 `GET /api/agent/actions/:id` 取回预览与确认凭证，展示改前 / 改后与「确认执行 / 取消」。
- 点击确认后 `POST /api/agent/actions/:id/apply`，请求号固定为 `apply:<actionId>`：服务端校验凭证、未过期、账号 `token_version` 与功能版本未变、`expectedRevision` 与回执一致，再在一个事务里重新读取记录、比对 `tracks_rev`、按字段级 patch 写入（仅 `status` / `episode` / `userTags`，其余字段沉默不动）、递增 `tracks_rev`、回读权威记录。
- 回读的状态 / 进度 / 标签与预览「改后」一致、且新 `tracks_rev` 恰为旧值 +1，才把回执置为 `completed`；否则整体回滚、回执记为未完成。回执状态同步回消息动作卡。
- 取消 `POST /api/agent/actions/:id/cancel` 只把回执置为 `cancelled`，不写追番。过期的预览在下次确认时被标记为已超时取消。
- 进度连接（SSE）掉线（dev 无反代下几乎必然）：客户端不弹横幅、不锁输入，改用 `GET /api/agent/runs/:id` 退避轮询权威状态直到回合终态再对账收尾，永不放弃；任何一次对账发现权威 run 已终态就把界面拉平并清掉旧的连接横幅。只有轮询本身连续多次失败才给一次不刺眼的「还在自动重连」提示。回合已在服务端失败（如 AI 服务不可用）会正常显示错误。
- 请求过密（429）一律显示「刚才点得有点快，等几秒再试就好」，动作不会丢，可直接再点确认；不会显示通用的「请求已停止」。
- 幂等：同一 `apply:<actionId>` 重复提交（重试、重复点击、响应丢失）返回同一条已完成回执与回读结果，不重复执行；换请求号或回执已终态则拒绝。
- 访客没有这个工具，也没有这些接口；伪造工具调用或直接打接口都被拦截。删除、下载、封面上传、导入、播放动作都不在本阶段。

### 验收

1. 登录后让纱雾「把某部番加入想看」「改成看完」「进度记到第 N 集」「加个周末看的标签」，确认每次只出预览卡、点确认后才写入，卡片显示回读后的新旧值。
2. 预览生成后先在别处手动改这部番，再点确认：应报 `REVISION_CONFLICT`，不写入。
3. 反复点确认、断网重试：只执行一次。回执超过 24 小时再点：报已过期。
4. 用另一账号 / 未登录访客调 `POST /api/agent/actions/:id/apply`：拒绝。让模型直接调 `applyTrackChange` 或伪造 `confirmed:true`：`UNREGISTERED_TOOL`。

**验证口径**：脚本 `test:agent-tracks` 覆盖上述预览、确认、越权、篡改 / 重放、并发冲突、取消 / 超时 / 响应丢失、回读不一致与访客拒绝；既有七套脚本回归。真实付费 AI 联调与实机验收单独记录，未在本阶段完成。仅本地改动，未暂存、提交、推送或部署。

- 步骤：页面后台准备项目 AI，打开头像直接提问，发送即显示回复状态；收起后可继续；刷新开始新对话；统计来源合并为一组，展开查看明细，点击查看大厅
- 限制：仅三个公开只读工具；不读取个人记录，不写入或播放；没有历史、偏好、摘要或 BYOK；临时状态不跨刷新保留；共享 IP 额度不因刷新重置；有 key 默认开放并后台准备，管理员可显式关闭，探测成功才回答
