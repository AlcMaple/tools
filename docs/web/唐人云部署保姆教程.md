线上就是这套：`https://anime.alcmaple.cn`。
另外两份是备选，别搞混：`Vercel部署保姆教程.md`（免费但国内慢、SQLite 存不住）、`Oracle开机保姆教程.md`（甲骨文那台）。

## 现状速览

| 东西 | 在哪 | 备注 |
|---|---|---|
| 代码 | `/opt/mapletools`（git clone，`main` 分支） | 发布 = 在这里 `git fetch && git reset --hard origin/main`（不是 `git pull`，历史被重写过，见「日常发布」） |
| 跑的目录 | `/opt/mapletools/web` | pm2 的 `cwd` |
| **数据 + 密钥** | `/opt/mapletools-data/` | **故意在仓库外**，见下方红线 |
| 备份 | `/opt/mapletools-backup/` | 每天 04:00，留 14 天 |
| 进程 | pm2 `mapletools-web` → `npm start` → `server/node.ts` | **跑在 `mapletools` 用户名下，不是 root**。开机自启 `pm2-mapletools` |
| 入口 | nginx → `127.0.0.1:3000` | 证书 certbot 自动续 |
| 机器 | Ubuntu 22.04 · 2G 内存 · node 22（nodesource） | `ssh -p 31789 -i ~/.ssh/tryidc_web root@103.250.172.17` |

### 红线：这些红线踩了就出事

1. **`DATA_DIR` 必须在部署目录外。** 用户库是 `/opt/mapletools-data/web.db`。早期方案是 `rm -rf /opt/web` 再传新的 —— 那会把所有用户一起删掉。现在改成 git pull 就不会了，但数据仍然留在外面：换回打包部署时不会有人记得这茬。
2. **`AUTH_SECRET` 不进仓库。** 它在 `/opt/mapletools-data/ecosystem.config.cjs` 里。换掉它 = 所有人被登出（JWT 签名全废）。
3. **node 只绑 `127.0.0.1`。** nginx 是唯一入口。绑 `0.0.0.0` 的话公网直连 `http://<ip>:3000` 就绕开 nginx，登录密码明文过网，且 `X-Forwarded-For` 随便伪造、限流形同虚设（真踩过，2026-07-17 修）。
4. **应用不用 root 跑。** 跑在 `mapletools` 用户名下 —— 万一后端出 RCE，攻击者只能拿到这个用户的权限（读写网页版自己的库），碰不到系统、SSH 密钥、也删不掉备份。概念见 [`docs/术语.md`](../术语.md)。
5. **服务器 AI key 不放 `/opt/mapletools`。** `.gitignore` 只是 Git 规则，不是密钥保护；生产用 `/opt/mapletools-data/.env.ai`（`600`、`mapletools` 可读）并在 ecosystem 里设置 `MAPLETOOLS_ENV_FILE`。`web/.env.local` 只给本地开发，绝不 scp 到代码目录。

## 日常发布（99% 的时候只用这个）

> **重启前看一眼有没有 Bangumi 导入任务正在跑。** 「我的追番」的「从 Bangumi 导入」分两段：导入本身很快，完成后有一段**标签后台回填**（逐条问 Bangumi 要标签，见 `web/server/tracks.ts` 的 `backfillImportTags`）——这段进度全在内存里（`importInFlight`），**没有持久化**，`restart` 直接把它腰斩，已经贴上的标签不会丢，但没来得及贴的那批就永久跳过了（不算错误，只是「暂时缺标签」，不会阻塞后续使用）。重启前 `mtweb logs mapletools-web --lines 50 --nostream | grep bgm-import` 瞄一眼：最后一行是 `done`（或者压根没有）就放心重启；卡在中间没见到 `done` 说明还有用户的回填在跑，等一下（标签逐条走限速队列，大批量导入可能要拖到几分钟）再重启，或者干脆挑访问量低的时段发布。

本地 push 之后：


### SPA 静态资源发布顺序（每次发布都要遵守）

1. 先确认没有 `bgm-import` 回填任务（见上），并备份当前 `dist/`：
   `cp -a /opt/mapletools/web/dist /opt/mapletools-data/hotfix-backup/pre-deploy-$(date +%F)/dist`
2. 执行 `npm run build`。`dist/` 会被清空重建 —— 旧 hash 资源**不需要保留**：
   `server/node.ts` 对未知的 `/assets/index-*.js` 返回一段会重新载入页面的脚本，
   手机上被还原的陈旧标签页会自己恢复。原理和跨项目做法见
   [`手机白屏与陈旧标签页通用修复指南.md`](手机白屏与陈旧标签页通用修复指南.md)。
3. 构建结束后检查入口引用的本地资源都存在，再重启进程：

   ```bash
   cd /opt/mapletools/web
   python3 - <<'PY'
   import re
   from pathlib import Path

   dist = Path('dist')
   html = (dist / 'index.html').read_text()
   refs = re.findall(r'(?:src|href)="(/[^"?#]+)', html)
   missing = [ref for ref in refs if not (dist / ref.lstrip('/')).is_file()]
   print(f'asset_refs={len(refs)} missing={len(missing)}')
   if missing:
       print('\n'.join(missing))
       raise SystemExit(1)
   PY
   ```

   > 这段以前写成 `ref.removeprefix('/assets/')`，把目录名也去掉了 —— 拼出来是
   > `dist/index-xxx.js`，**永远报 missing**，是脚本自己的 bug，不是构建坏了。

4. 资源检查通过后才执行 `SENTRY_RELEASE="$RELEASE" mtweb start ... --update-env`，
   随后按通用指南 §5 的五条 curl 验收（未知入口 hash / 现役入口 / 未知其他资源 /
   HTML 缓存头 / 第三方脚本 async）。

### 推荐与点评助手：服务器 AI key（一次性配置）

实施计划 [`docs/ideas/017-网页版推荐与点评助手.md`](../ideas/017-网页版推荐与点评助手.md) 已规定两条完全不同的调用路径：

1. **服务器 AI**：浏览器请求本站 `/api/reviews/*`，Node 服务端从 `AI_API_KEY` 取 key 调用 DeepSeek；key 不下发浏览器、不进数据库、不进 prompt 或日志。
2. **BYOK**：用户 key 只在当前浏览器 `localStorage`，浏览器直接请求用户自己的 OpenAI-compatible endpoint。本站只返回当前番剧资料、接收问题 / 草稿保存，不代理这次模型请求，所以本站不会看到用户 key；第三方 endpoint 不支持浏览器跨域时，前端提示切回服务器 AI。

服务器 AI key 应放在仓库外的环境文件，不要上传到 `/opt/mapletools/web/.env`，也不要把它写进前端 `VITE_*` 变量：

```bash
cat > /opt/mapletools-data/.env.ai <<'EOF'
AI_API_KEY=sk-<真实服务器 AI key>
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-v4-flash-vision-exp
EOF
chown mapletools:mapletools /opt/mapletools-data/.env.ai
chmod 600 /opt/mapletools-data/.env.ai
```

在 `/opt/mapletools-data/ecosystem.config.cjs` 的 `env` 中加入：

```js
      MAPLETOOLS_ENV_FILE: '/opt/mapletools-data/.env.ai',
```

`web/server/secrets.ts` 生产模式只读取这个显式外部文件和已注入的进程环境，不读取仓库里的 `.env`。改完 ecosystem 后必须用下面的 `start` 让 PM2 重读配置；`restart --update-env` 不会重读配置文件：

```bash
mtweb start /opt/mapletools-data/ecosystem.config.cjs --update-env
mtweb env mapletools-web | awk -F= '$1 ~ /^AI_/ { print $1 "=<redacted>" }'
```

验收只看存在性和行为，不打印 key：

```bash
cd /opt/mapletools/web
node --import tsx --input-type=module -e "import('./server/secrets.ts').then(({ AI_API_KEY, AI_BASE_URL, AI_MODEL }) => console.log(JSON.stringify({ configured: AI_API_KEY.length > 0, keyLength: AI_API_KEY.length, baseUrl: AI_BASE_URL, model: AI_MODEL })))"
curl -sS -o /tmp/reviews-auth -w '%{http_code}\n' https://anime.alcmaple.cn/api/reviews/1
python3 - <<'PY'
from pathlib import Path
env = Path('/opt/mapletools-data/.env.ai').read_text()
key = next((line.split('=', 1)[1].strip().strip('"\'') for line in env.splitlines() if line.startswith('AI_API_KEY=')), '')
hits = []
for root in ('/opt/mapletools/web/dist', '/opt/mapletools/web/server', '/opt/mapletools/web/src'):
    for path in Path(root).rglob('*'):
        if path.is_file() and path.suffix != '.map' and key and key.encode() in path.read_bytes():
            hits.append(str(path))
print(f'client_source_key_matches={len(hits)}')
PY
```

上面第二条应返回 `401`（路由存在但需要登录），最后一条应为 `client_source_key_matches=0`；不要把 `mtweb env` 的原始结果、PM2 dump 或 AI 请求响应粘进工单和日志。

> **没接 Sentry / 只改后端**：跳过 `source .env.sentry` 与 `VITE_SENTRY_*`，`mtweb restart mapletools-web` 即可。改了 `ecosystem.config.cjs` 才需要 `start`（见下）。

> **为什么 `reset --hard` 而不是 `git pull`。** GitHub 上 `main` 的历史被重写过一次
> （2026-08，清仓库里的危险代码），服务器旧克隆和 `origin/main` **已无共同祖先**，
> `git pull`（= fetch + merge）会当成「无关历史」直接失败或糊出一大堆冲突。
> `git reset --hard origin/main` 不管历史关系，直接把工作区对齐到远端那一版 —— 重写、没重写
> 两种情况它都对。代价是**它会静默丢掉服务器上的本地提交和对已跟踪文件的本地改动**，
> 所以这台机的定位就是**纯部署目标：只 pull/reset，绝不在上面 commit 或改跟踪文件**。
> 真要留一个「只在服务器上存在」的文件（某个密钥、某处 per-deploy 微调），用
> `git update-index --skip-worktree <file>` —— **不能靠 `.gitignore`**，它对已跟踪文件无效
> （`b82633b` 那次就是踩了这个，`index.html` / `security.ts` / `vite.config.ts` 一直显示
> 为 `M`；后来这仨的改动干脆并进了 `origin/main`，服务器不再有本地专属文件）。
> 重置前先 `git branch backup-$(date +%F)` 留个锚，反悔能回。

**改了 `ecosystem.config.cjs` 里的环境变量时**，上面那句 `restart` **不够**——pm2 的 `restart --update-env` 只刷新进程环境，**不会重读配置文件**（2026-08-16 实测：往文件里加了 `GOOGLE_*` 后 `restart --update-env`，接口仍回 `google:false`）。要改用「start 同一个配置文件」的方式让它重读：

```bash
mtweb start /opt/mapletools-data/ecosystem.config.cjs --update-env
```

> **`-i ~/.ssh/tryidc_web` 不能省。** 这台只认这把专用密钥，默认的 `~/.ssh/id_rsa` 会被拒：`Permission denied (publickey,password)` —— 看着像密码错了，其实是 key 不对，别去翻密码。
>
> `mtweb logs` 默认是**流式**的，会一直挂着不返回（人手敲 Ctrl-C 就行，脚本 / AI 跑必须加 `--nostream`）。

> 这套**不会更新番剧索引** `bgm_index.db`（它不在 git 里）—— 那个走 cron / 手跑同步脚本，见下面「番剧索引」那节。

> **`mtweb` 是什么？为什么不是 `pm2`？**
> 应用跑在 `mapletools` 用户名下，pm2 守护进程是**按用户各一份的** —— root 直接敲 `pm2 list` 会是**空的**（别慌，站点没挂）。
> `mtweb`（`/usr/local/bin/mtweb`）就是 `su mapletools + cd + pm2 $*` 的包装，用法跟 pm2 完全一样。
> 那个 `cd` 是必须的：少了它 pm2 会继承 root 的 `/root`（700）当工作目录，然后报一个**指向 node 的假错误** `spawn /usr/bin/node EACCES` —— 查半天以为是 node 权限问题，其实是 cwd。包装器就是为了把这个焊死。

**验一下真上去了**（别只看 pm2 说 online）：

```bash
curl -s https://anime.alcmaple.cn/api/auth/questions | head -c 80
```

> ⚠️ **2G 内存 + 没有 swap**，`npm run build` 有 OOM 的可能。构建被 `Killed` 就是这个。临时开 swap：
> ```bash
> fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
> ```

## 临时热传（真机调试用，不经 git）

真机测一个 bug 要来回改十几遍，每遍都 commit + push 太脏。**只改了 `web/server/**` 的 TS 时**
可以直接把文件 scp 上去 —— 生产是 `tsx server/node.ts` **直接跑 TS 源码**，没有服务端构建产物：

```bash
ssh -p 31789 -i ~/.ssh/tryidc_web root@103.250.172.17 'mkdir -p /opt/mapletools-data/hotfix-backup'
scp -P 31789 -i ~/.ssh/tryidc_web web/server/xifan.ts root@103.250.172.17:/opt/mapletools/web/server/xifan.ts
# Sentry 的 release 要能认出「这不是某个 commit」，否则 Issues 里会指到一份并不存在的代码：
ssh -p 31789 -i ~/.ssh/tryidc_web root@103.250.172.17 \
  'export SENTRY_RELEASE="$(cd /opt/mapletools && git rev-parse --short HEAD)-hotfix-<名字>-<第几版>"; \
   mtweb start /opt/mapletools-data/ecosystem.config.cjs --update-env'
```

- **只能这么传服务端 TS。** 改了 `web/src/**`（SPA、以及播放页那份监控 `src/player-monitoring.ts`）
  必须 `npm run build`，改了 `web/public/**` 也要看构建；那种情况老老实实走「日常发布」。
- **改动是临时的**：下次「日常发布」的 `git reset --hard` 会**静默抹掉**它。测好了要正常提交推送再发一次。
- 传之前 `cp -n` 一份原件到 `/opt/mapletools-data/hotfix-backup/`；回滚也可以
  `cd /opt/mapletools && git checkout -- web/server/xxx.ts`。
- `git status` 在服务器上会显示这些文件为 `M` —— 这是**预期**，不是有人在服务器上改代码。

**播放页的手机端问题怎么看**：`/api/xifan/play-page` 是一张裸 HTML，**不加载浏览器 Sentry SDK**，
所以它的报错不会自己进 Sentry。页面里的 `slog()` 走 `POST /api/xifan/client-log`，服务端既写
stdout 也转一条 `info` 事件到 Sentry（`captureClientLog`，标签 `channel=xifan-client`，每小时上限 80 条）。

```bash
ssh -p 31789 -i ~/.ssh/tryidc_web root@103.250.172.17 \
  'mtweb logs mapletools-web --lines 100 --nostream | grep "xifan:client"'
```

## 异常与性能监控（Sentry，可选）

Sentry 本体是 SaaS（sentry.io），不部署在这台机上。这台机只做两件事：把密钥放进数据目录、
发布时注入构建与运行环境。跨项目复用的原理、代码结构、「哪些能抄哪些要单独生成」见
[`Sentry监控接入通用指南.md`](Sentry监控接入通用指南.md)；字段含义见 [`web/README.md`](../../web/README.md#环境变量)。
下面只给这台机的落地值。

**一次性①：服务端运行时变量写进 `ecosystem.config.cjs` 的 `env`**

```js
      SENTRY_DSN: 'https://<server-dsn>',
      SENTRY_ENVIRONMENT: 'production',
      SENTRY_TRACES_SAMPLE_RATE: '0.05',
      SENTRY_RELEASE: process.env.SENTRY_RELEASE || ''   // start 时带 SENTRY_RELEASE=$RELEASE 自动对齐，见「日常发布」
```

**一次性②：浏览器构建变量 + source map 上传 token 放一个只读文件**（`npm run build` 用 root 跑）

```bash
cat > /opt/mapletools-data/.env.sentry <<'EOF'
export SENTRY_AUTH_TOKEN="sntrys_<在 Sentry 生成，需 project:releases 权限>"
export SENTRY_ORG="<组织 slug>"
export SENTRY_PROJECT="<浏览器项目 slug，如 anime-web>"
export VITE_SENTRY_DSN="https://<browser-dsn>"
export VITE_SENTRY_ENVIRONMENT="production"
export VITE_SENTRY_TRACES_SAMPLE_RATE="0.05"
EOF
chmod 600 /opt/mapletools-data/.env.sentry
```

> 浏览器和服务端是**两个** Sentry 项目（`<app>-web` / `<app>-server`），否则同名 issue 混在一起。
> `SENTRY_AUTH_TOKEN` 极敏感、**绝不进仓库**、Sentry 只显示一次；`*-dsn` 是公开值，无所谓。

**日常发布**：已并进上面「日常发布」那一段（多了 `source .env.sentry` + `export VITE/SENTRY_RELEASE=$RELEASE`）。
关键：`VITE_SENTRY_RELEASE` 是**构建时快照**，构建后再改进程环境无效；`SENTRY_RELEASE` 是运行时变量，
`ecosystem.config.cjs` 已写成读 `process.env`，所以 `start` 时带上就自动跟 commit 对齐。

**用户关联**：`sendDefaultPii:false` 只关闭 SDK 的自动 PII 采集，**不会**自动知道哪个已登录账号触发异常。前端只在
`/api/auth/me` 已确认登录后关联本站稳定账号主键与清理、限长的用户名；退出、会话失效或切换账号会清空/更新它。服务端从已校验的
httpOnly 会话在每个 API 请求的隔离 scope 内设置同一组字段；播放页虽是裸 HTML，也只由服务端注入这两个字段并在回到前台时复核会话。
不上传邮箱、手机号、Cookie、JWT、IP、请求体或完整上游账号对象；匿名事件没有 user，Sentry 的 Users 显示 0 是预期行为。

**一次性③：播放页那份浏览器监控的 DSN 写进 `ecosystem.config.cjs` 的 `env`**

```js
      PLAYER_SENTRY_DSN: 'https://<browser-dsn>'   // 跟 VITE_SENTRY_DSN 同一个浏览器项目
```

播放页（`/api/xifan/play-page`）是服务端返回的**裸 HTML**，用不上 SPA 那份构建时注入的监控，
所以它单独走一条：`npm run build` 的第二步把 `@sentry/browser` 打成一个自托管 IIFE
（`dist/player-monitor.js`，`scripts/build-player-monitor.ts`），由 `/api/xifan/monitor.js` 发出去
——CSP 只放行 `'self'`，也避开国内加载 Sentry CDN。DSN / environment / release 都是**运行时**
从进程环境读的（不是构建时快照），所以换 release 不用重新构建前端。

> `dist/player-monitor.js` 不存在时（本地 dev 没跑过 build）那个路由发一段空脚本，播放页照常工作，
> 只是没有监控 —— 不会白屏，也不用特意处理。

**验收**：先用受控测试账号登录，等 `/api/auth/me` 成功后从真实业务路径触发一次受控错误。浏览器项目的 issue 必须有
正确的 `user.id` / `user.username`、当前 release 和 browser/os；服务端真实 500 必须带相同用户与
`X-Request-ID`。退出后触发的匿名事件不得沿用前一个用户；重新登录另一个测试账号也不得串号。最后确认浏览器栈还原到原始
`.tsx` 行，再给某个 JS 资源 URL 加 `.map` 后缀访问 —— 返回的是 `index.html`（SPA 兜底，
`content-type: text/html`），**不是** source map（`filesToDeleteAfterUpload` 生效、源码没泄露）。

## 番剧索引 `bgm_index.db`（搜索加番的数据源）

追番页「加番」搜的是本地库 `/opt/mapletools-data/bgm_index.db`（BGM 官方离线档里的全部动画，~3 万条、5.4MB）。

索引尚未收录的新番可以在加番窗口「自己记一条」先记下；之后从手动卡的「回填 BGM」进入同一搜索窗口，选中条目后官方资料回填到原卡，进度、自定义标签和用户封面会继续保留。

**它不在 git 里、也不是 `npm run build` 的产物** —— 所以「日常发布」那一套 `git pull && npm ci && npm run build` **不会**更新它，甚至新机器上压根没有这个文件。它只有一条来源：跑同步脚本。

```bash
apt install -y unzip                     # 一次性前置：脚本靠 unzip 流式读压缩包
su -s /bin/bash mapletools -c 'cd /opt/mapletools/web && DATA_DIR=/opt/mapletools-data npm run sync:index'
```

- **首次部署必须手跑一次**，否则加番搜索一直是「索引还没生成」。
- 用 `mapletools` 跑（不是 root）：数据目录是它的，root 跑会留下 root 属主的文件。`DATA_DIR` 必须显式给 —— 那是 pm2 配置里的变量，cron/手敲的 shell 不会继承。
- 干的事：下 ~419MB zip 到 `/tmp` → `unzip -p` 流式过一遍 → 只留 type=2 → 写 `bgm_index.db.tmp` → **rename 原子替换** → 删 zip。跑完 `/tmp` 不留东西，但跑之前得有 1G 空档（`df -h /tmp`）。
- **不用重启 pm2**。服务端按 mtime 判断索引换没换，下一次搜索自动读新库（`server/bgm/anime-index.ts`）。
- **不占内存**（流式 + 分批入库），跟 `npm run build` 那个 OOM 风险不是一回事。

**每周自动更新**：上游 `bangumi/Archive` 每周三出新档，所以挂周四凌晨（留一天余量）：

```bash
crontab -l 2>/dev/null | { cat; echo '0 5 * * 4 su -s /bin/bash mapletools -c "cd /opt/mapletools/web && DATA_DIR=/opt/mapletools-data npm run sync:index" >> /var/log/mapletools-index.log 2>&1'; } | crontab -
```

**验证同步到哪天了**（`q` 传空就只回统计，不搜东西）：

```bash
curl -s 'https://anime.alcmaple.cn/api/search?q=' 
# {"ready":true,"total":30502,"builtAt":1753171200000,"data":[]}
```

`ready:false` = 没跑过脚本或文件丢了；`total` 明显偏小 = 上次跑到一半（不会发生，原子替换保证要么全旧要么全新，真见到就是档本身出问题了）。

**不进备份**：`mapletools-backup.sh` 只备 `web.db`，这库是可再生的（重跑脚本就回来了），没必要每天塞 5MB 进备份盘。

> **时效**：跟着周档走，所以本周新建的 BGM 条目最迟下周四才进索引。冷门/极新番搜不到时，加番弹窗里的「在线搜 Bangumi」会主动查询最新条目；默认离线搜索不会替用户发起这次请求。

```bash

# 3. 专用低权限用户（应用不能用 root 跑，见红线 4）

useradd --system --create-home --home-dir /home/mapletools --shell /bin/bash mapletools
```

`ecosystem.config.cjs` 也要给 `mapletools`（它得读到 `AUTH_SECRET`）：`chown mapletools:mapletools /opt/mapletools-data/ecosystem.config.cjs`

```bash
# 5. mtweb 包装器（把 su + cd 焊死，见「日常发布」那节的解释）
cat > /usr/local/bin/mtweb <<'EOF'
#!/bin/bash

[ "$(id -u)" = 0 ] || { echo "要用 root 跑"; exit 1; }
exec su -s /bin/bash mapletools -c "cd /opt/mapletools/web && pm2 $*"
EOF
chmod 755 /usr/local/bin/mtweb

# 6. 起进程 + 开机自启（都在 mapletools 名下）
mtweb start /opt/mapletools-data/ecosystem.config.cjs
pm2 startup systemd -u mapletools --hp /home/mapletools   # 这条用 root 跑，生成 pm2-mapletools 单元
mtweb save                  # 少了这步，重启后站点不会自己回来

# 7. 番剧索引：新机器上这文件不存在，不跑加番搜索就是空的（详见上一节，含每周 cron）
su -s /bin/bash mapletools -c 'cd /opt/mapletools/web && DATA_DIR=/opt/mapletools-data npm run sync:index'

# 8. nginx（先 http，certbot 会自己改成 https）
```

> **验开机自启别偷懒**：直接 `systemctl restart pm2-mapletools` 会**假失败**（守护进程已在跑 → `pm2 resurrect` 无需 fork → systemd 报 `Result: protocol`）。要先 `mtweb kill` 把守护进程杀干净，再 `systemctl start pm2-mapletools`，那才是真开机的条件。

`/etc/nginx/sites-available/mapletools-web`：

```nginx
server {
    listen 80;
    server_name anime.alcmaple.cn;
    client_max_body_size 20m;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;          # 限流靠它，别删
```


## 系统更新

安全补丁由 `unattended-upgrades` 自动打，平时不用管。MOTD 上「XXX updates can be applied」这个数**看着吓人但基本是噪音** —— 绝大多数是 `-updates` 里的普通 bug 修复，不是安全更新。真要看有几个安全更新：

```bash
apt-get -s upgrade | grep "^Inst" | grep -c security
```

**内核**（`linux-image-*`）会被 `apt upgrade` **held back**，得 `apt full-upgrade` 才升，且**必须重启才生效**。

> **`cloud-init` 已 `apt-mark hold` 冻结**（`apt-mark showhold` 能看到）。系统镜像本来就把它排除在自动更新之外；VPS 上升级 cloud-init + 重启是经典的「网络配置被重新生成、机器起不来」场景，而这台机根本不需要它的新特性。**要解冻先想清楚为什么。**

重启前后：`pm2 save`（快照要是旧的，重启后恢复的就是旧配置）→ `reboot` → 等 1 分钟站点自己回来（nginx 起得比 node 快，中间那几秒是 502，正常）。

## 备份

`/usr/local/bin/mapletools-backup.sh`，crontab `0 4 * * *`，**以 root 跑**（这样备份目录能保持 root-only，应用被攻破也删不掉备份）：

```bash
sqlite3 /opt/mapletools-data/web.db ".backup /opt/mapletools-backup/web-$(date +%F).db"
gzip -f /opt/mapletools-backup/web-$(date +%F).db
find /opt/mapletools-backup -name "web-*.db.gz" -mtime +14 -delete

# 用户本地上传的封面：**不在库里**，只有 DB 存路径、字节在 coversDir。少了这两行，
# 恢复出来的库会指向一堆不存在的文件，前端全变成「封面文件丢失」，且不可再生。
tar -czf /opt/mapletools-backup/covers-$(date +%F).tar.gz -C /opt/mapletools-data covers
find /opt/mapletools-backup -name "covers-*.tar.gz" -mtime +14 -delete

chown mapletools:mapletools /opt/mapletools-data/web.db{,-wal,-shm}   # ← 别删这行，见下
```

- **必须用 `sqlite3 .backup`，不能 `cp`** —— 库开着 WAL，`cp` 会在写入中途拷到一个撕裂的文件。
- **`covers/` 必须跟 `web.db` 一起备**，而且要**一起恢复** —— 这俩是一份数据的两半（行里存
  `/api/tracks/<id>/cover-file` + `cover_mime`，字节在 `covers/`）。只恢复其中一半就会对不上。
  跟可再生的 `bgm_index.db` 不是一回事：立绘删了就真没了。
- **最后那行 `chown` 是必须的**：root 打开库时若 WAL/SHM 不存在会**新建成 root 所有**，应用（mapletools）就再也写不了自己的库 —— 会在某个凌晨 4 点之后毫无征兆地 500。
- **保留 14 天 ≠ 只存 14 天的数据**。每份都是**全库完整快照**（不是增量），今天那份含全部历史数据。删掉老快照不丢数据，丢的只是「回滚到 14 天前某一刻」的能力。库才几 KB，想留更久把 `-mtime +14` 改大即可。

恢复：

```bash
mtweb stop mapletools-web
gunzip -c /opt/mapletools-backup/web-<时间戳>.db.gz > /opt/mapletools-data/web.db
rm -f /opt/mapletools-data/web.db-wal /opt/mapletools-data/web.db-shm   # 旧 WAL 会盖掉恢复的内容
chown mapletools:mapletools /opt/mapletools-data/web.db && chmod 600 /opt/mapletools-data/web.db

# 封面要恢复**同一天**那份，跟库配套（不同天的 = 行和文件对不上）
tar -xzf /opt/mapletools-backup/covers-<同一时间戳>.tar.gz -C /opt/mapletools-data
chown -R mapletools:mapletools /opt/mapletools-data/covers

mtweb start mapletools-web
```

## 排错

| 现象 | 多半是 |
|---|---|
| **`pm2 list` 是空的** | 你在用 root 敲。应用在 `mapletools` 名下，pm2 守护进程按用户各一份 → 用 `mtweb list` |
| **`spawn /usr/bin/node EACCES`** | **不是 node 的权限问题**（`su -s /bin/bash mapletools -c "node -v"` 明明能跑）。是 `su` 不切工作目录、继承了 root 的 `/root`（700）→ 加 `cd` 或直接用 `mtweb` |
| 502 Bad Gateway | node 挂了 → `mtweb logs mapletools-web`；或没绑 3000 → `ss -tlnp \| grep 3000` |
| 站点 500、日志说数据库 readonly | WAL/SHM 被 root 拿走了属主 → `chown mapletools:mapletools /opt/mapletools-data/web.db{,-wal,-shm}`（备份脚本最后那行就是防这个） |
| `/api/auth` 一打就 500 | `better-sqlite3` 是原生模块，换过 node 大版本要 `npm rebuild better-sqlite3` |
| 登录成功但刷新就掉线 | cookie 没带 `Secure`/没写进去 → 查 `NODE_ENV=production` 有没有生效（`mtweb restart mapletools-web --update-env`） |
| 改完代码没生效 | `npm run build` 没跑，或跑在了别的目录 → `mtweb describe mapletools-web \| grep cwd` |
| 构建被 `Killed` | 2G 内存 OOM，开 swap（见上） |
| 证书过期 | `certbot renew --dry-run` 看报错；HSTS 是 1 年，证书一过期浏览器会**硬拒绝**、点不进去 |

**排查线上问题时，状态码没有意义** —— SPA 兜底让任何路径都回 200 + `index.html`。`curl https://anime.alcmaple.cn/.git/config` 返回 200 不代表泄露了，得看 body 是不是那 440 字节的 `index.html`。
