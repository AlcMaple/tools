## 〇、和文章的对应（2026-11-04 定稿口径）

文章 Q2 原话：人天「可以算，但不該只用它當定價基礎」，建议拆成几块分开计价。所以：

- **内部可以按小时算成本**（你的不接线），这不和文章冲突
- **报价单上不出现小时和天**，客户看到的是每一块的一口价、包含 / 不包含、交期
- 文章第三条的「需求诊断」不做：这个功能在拿到需求之后才用，诊断不收费

报价单固定三块，每块都收钱：

| 块 | 内容 | 内部怎么算（客户看不到） |
|---|---|---|
| 交付 | 需求清单里的东西做出来，固定范围、交期、价格 | 清单每条小时 × 时间值（新做 / 接手改分开）+ 每个未说清的点一笔风险垫 |
| 兜底 | 14 天保修，出问题立刻响应只修这一件到解决为止；什么算问题写死 | 按未说清的点数估可能要修的小时 × 时间值 |
| 结果 | 商单：成效奖金（达标才付）；学生单：改到答辩通过；玩具单：装好并教会 | 预计修改轮数的小时 × 时间值；商单奖金和客户按指标谈 |

### 多版本时的反馈

- 需求每变一次生成新版本，旧版本只是草稿，**不回填任何反馈**
- 发给客户的那一版标为「已报价」；最终签下的那一版标为「已成交」
- 客户结果（成交 / 嫌贵 / 没回音、预算）只记在「已报价」那一版
- 实际小时和亏 / 值只记在「已成交」那一版，只用来修正时间值和小时估计，不直接改价格

## 一、先回答根本问题：「正确的价格」是什么

市面上没有正确的价格，这一点是对的，所以不去找「市场价」。谈判理论给了另一个定义，这是整个方案的地基：

> **一单的合适价格 = 落在「双方都能接受的区间」里的价格**
> 出处：Fisher & Ury《Getting to Yes》(1981) 的 BATNA，及哈佛谈判项目对 ZOPA（Zone of Possible Agreement，可成交区间）的定义

```
你的底线 ─────────[ 可成交区间 ]───────── 客户的上限
（低于它你宁可不接）                    （高于它他宁可不做 / 找别人 / 自己 AI 做）
```

- 区间存在 → 报价落在区间里，双方都能接受，这就是「正确」
- 区间不存在（客户上限 < 你的底线）→ **没有任何价格是正确的**，唯一的解是缩范围，不是降价。200 块毕设就是这种：不是你报错了，是这单在这个范围下不存在成交价
- 所以报价工具要做的不是「算出一个价」，而是**分别弄清两端，再找交集**

## 二、你的底线怎么定（有依据，不靠市场）

底线 = 你接这单放弃掉的东西（经济学的机会成本；BATNA 里「不成交时你的最佳替代」）。它只跟你自己有关，跟别人 200 块做毕设无关

```
底线 = 预计投入小时 × 你的时间值 + 风险垫 + 实际支出
```

| 项 | 怎么来 | 依据 |
|---|---|---|
| 预计投入小时 | 不是「写代码的时间」：AI 时代写代码近乎零，真正花时间的是沟通、确认、调试、部署、返工、交付后答疑。按需求清单逐项估，每项写清理由 | 文章「真正花掉我時間的，從來不是把文章寫出來」 |
| 你的时间值 | 你自己填一次：这段时间不接单，你能拿它换到什么（上班时薪 / 别的单的成交均价 / 休息值多少）。不是市场价 | 机会成本 |
| 风险垫 | 需求里每一个「客户还没说清」的点各加一笔，写明是哪一点 | 未定项就是返工来源 |
| 实际支出 | 服务器、域名、付费接口、素材授权 | 直接成本 |

**校准**：每单结束后记一次「实际花了多少小时」。前几单靠估，十几单后预计投入小时由你自己的历史给出（同类需求的实际均值），这是唯一可信的数据来源，比任何公式都准

## 三、客户的上限怎么弄清（不猜，问）

上限由三样东西决定，工具负责把它们从材料里找出来，找不到就生成要问客户的问题：

| 要弄清的 | 为什么决定上限 | 问法示例 |
|---|---|---|
| 预算 | 最直接的上限 | 「这个你大概准备多少预算」 |
| 不做的后果 | 文章：价格绑客户在意的结果。毕设不交 = 延毕；商单掉单 = 损失多少钱；玩具不做 = 没什么损失 | 「哪天之前必须拿到，晚了会怎样」 |
| 他的替代方案 | 客户的 BATNA：自己 AI 做、找同学、找别家、不做了 | 「自己试过吗，卡在哪」 |

文章 Q3 的回法就是这一项：客户说「我自己 AI 能做」，那是他的替代方案，你要报的是他替代方案做不到的那部分（上线、兜底、改到通过）

## 四、需求无限怎么办：范围跟着区间走，不是价格跟着需求走

| 做法 | 依据 |
|---|---|
| 需求逐条拆，每条标 **必须 / 应该 / 可以 / 这次不做**，每条单独挂小时和理由 | MoSCoW 优先级法（Clegg, DSDM, 1994），敏捷项目通用的范围控制方法 |
| 区间不存在时，从「可以」开始往下砍，直到底线 ≤ 客户上限；砍掉的写进「不包含」 | 同上：固定时间和预算，范围是变量 |
| 签的是需求清单 + 不包含清单，不是工时 | 文章「固定範圍、固定交期、固定價格」 |
| 清单外的新想法一律走变更单：同一套方法给一张小报价 | 文章第四条「驗收跟救火寫進報價單」 |

脑洞无限没关系：每一个新想法只是清单上多一行，带自己的小时和价格，客户自己决定要不要

## 五、三档怎么来：不是事先定死的套餐，是同一份清单的三种切法

上一版的「事先定好三档价格」撤回：那需要你凭空定价，正是你说的「定高不行、定低不行」

```
基础档 = 只含「必须」          → 价格 = 这部分的底线（不加溢价）
推荐档 = 必须 + 应该 + 兜底     → 你主推的那档
完整档 = 全部 + 更长兜底 + 加急
```

- 依据：三档并列时，中间档被选中的比例显著上升（诱饵效应 / 不对称占优，Huber, Payne & Puto, *Journal of Consumer Research*, 1982）；先给出的数字会成为对方判断的锚（Tversky & Kahneman, *Science*, 1974），所以完整档放在最前
- 每档的价格都能逐行展开到「哪一条需求、几小时、为什么」，这就是「每一笔都算清楚」
- 兜底按文章单列：保修天数、响应时间、改到什么程度为止

## 六、不同客户、人情世故：明着写，不暗里改价

| 情况 | 处理 | 理由 |
|---|---|---|
| 学生、熟人、老客户、想积累作品 | 报价单上**原价照写**，下面单列一行「人情折让 −X（原因：同学 / 老客户第 3 单 / 作品授权给我展示）」 | 原价不动，锚还在；下次不会被当成「原来就值这么多」。折让写原因，对方知道这是情分不是常态 |
| 你想要作品集、想练某个技术 | 同上，折让原因写「换作品展示权」，并写进条款 | 你拿到的东西明确化 |
| 客户只想先问价 | 只给区间（基础档 ~ 完整档），清单和问题完整给 | 判断力不白送：清单是你的产出 |
| 商单、有可测指标 | 推荐档之上加一项「成效奖金」：基线、目标、验证方式、金额 | 文章：固定建置費 + 成效獎金，客戶心理門檻最低 |
| 老客户续单 | 可改月维护 + KPI 区间奖金 | 文章：適合已經合作過一輪的客戶 |
| 底线 > 客户上限，且砍到「必须」也不行 | 工具直接说「这单在这个预算下不成立」，并给出能成立的最小范围 | 不存在的区间不硬凑 |

折让上限由你设一次（例如不低于底线的 N%），工具不会让人情价跌穿你自己定的线

## 七、新流程

```
材料（保留现有：文字/截图/网址/文档/视频/压缩包/表格）
  → ① 需求整理：拆成需求清单，每条：内容 / 必须-应该-可以-不做 / 预计小时 + 理由 / 是否未定
             同时找出：客户类型、预算、不做的后果、替代方案；找不到的变成「要问客户的问题」
  → ② 底线：清单小时 × 你的时间值 + 风险垫（逐条对应未定项）+ 实际支出
  → ③ 区间判断：有预算 → 比对底线，不成立就给最小可成立范围；没预算 → 只出三档
  → ④ 三档 + 兜底 + 人情折让（你手动选）+ 成效奖金（商单可选）
  → ⑤ 报价单：客户版（清单、不包含、三档、兜底、折让）/ 自用版（加上底线和每条小时）
  → 成交 / 没成交 / 结束后实际小时 回填 → 校准下一单的小时估计
```

AI 只做①（整理、分类、提问）和逐条小时的初估；②~④全是确定的计算，每一个数都能点开看来源。小时初估在你有历史后改为参考你同类需求的实际值

### 兜底的边界（必须写进报价单，否则「修到解决为止」没有尽头）

修复时长无法衡量没关系，承诺的是「只做这件事直到解决」，但**什么算问题**必须写死：

- 算：需求清单里写了的功能，在交付时的环境下不工作
- 不算：清单外的新想法、客户自己改了代码 / 环境 / 第三方服务后出的问题、14 天后发现的问题 → 走变更单
- 因为修复时长不可控，这部分成本放进底线的风险垫：每单按「需求清单里未定项数量」加垫，不另收兜底费

### 时间值：不问「你值多少」，问你会怎么选

没人能直接答出自己的时间值，这是正常的。劳动经济学的做法是看人在具体选择里怎么选（保留工资 reservation wage：让一个人愿意去干活的最低报酬），而不是让他报数。工具首次使用时问三道选择题，你只需要答「接 / 不接」：

1. 一个周末两天，全天做一个你不感兴趣的单子，给你 X 元，接不接？（X 从低往高逐档问，找到你开始说「接」的那一档）
2. 一个晚上 3 小时，改一个别人写坏的项目，给你 Y 元，接不接？
3. 同上，但客户沟通很磨人，要反复确认，给你 Z 元，接不接？

时间值 = 三题的「刚好愿意接」价格各自除以小时数，取中间那个。第 3 题比第 1 题高出的部分，就是你对「难缠客户」的额外要价，可以直接用作风险垫的参考

#### 答题结果（2026-11-04）

| 题 | 刚好愿意接 | 折合每小时 |
|---|---|---|
| 周末 16 小时，从零做一个不感兴趣的单子 | 500 | 约 31 |
| 晚上 3 小时，修别人写坏的项目 | 800 | 约 267 |
| 同上，客户磨人要反复确认 | 800 | 约 267 |

三个数差了 8 倍，取中间值会得到一个两头都不对的数，所以不合成一个时间值，按答案本身的含义拆开用：

- **从零做和接手旧代码是两种价**：从零做（AI 时代没门槛）约 31/小时；接手、修别人的代码约 267/小时。需求整理时每条需求标「新做 / 接手改」，各用各的时间值
- **难缠客户不加价**：第 3 题和第 2 题一样，说明沟通磨人对你不构成额外成本，风险垫只按「需求未定项」加，不按客户性格加
- 这组数来自假设题，成交后按下面的规则用真实选择修正

### 修正规则

每次报价记下「每小时价格 = 报价 ÷ 预计小时」和你的选择：

| 发生的事 | 判断 | 修正 |
|---|---|---|
| 每小时价格高于时间值，你自己不想接 | 时间值偏低 | 提高到这单的每小时价格 |
| 每小时价格低于时间值，你接了且做完觉得值 | 时间值偏高 | 降到这单的每小时价格 |
| 实际小时远超预计、觉得亏 | 小时估少了，不是时间值的问题 | 修这类需求的小时估计 |
| 客户嫌贵没成交 | 客户上限，与你无关 | 不动 |

数据攒多后，时间值 = 你拒绝过的最高每小时价格与接受过的最低每小时价格的中间值，按「新做 / 接手改」分别算。自己拒掉的单也必须记，否则无法修正

之后每成交一单，用「成交价 ÷ 实际小时」回看：你接了的单子都高于这个数、拒绝的都低于它，说明它是准的；对不上就按实际选择修正。你的选择比你的回答更可信

### 反馈与自动纠正

每条报价只需你回填两次，全部是点选，数字只填一个：

```
报价发出后 → 客户结果：成交 / 嫌贵没成交（客户说了预算就填） / 没回音
做完后     → 实际花了几小时 + 觉得：亏 / 刚好 / 值
```

系统自动做三件事，彼此分开，不混在一起：

| 回填 | 自动纠正什么 | 怎么算 |
|---|---|---|
| 实际小时 | 小时估计 | 同类需求（新做 / 接手改）「实际 ÷ 预计」取中位数，下次初估乘这个系数 |
| 亏 / 刚好 / 值 | 时间值 | 用实际小时算「成交价 ÷ 实际小时」：亏 ⇒ 时间值一定高于它；值 ⇒ 时间值不高于它；刚好 ⇒ 就是它。时间值 = 所有「亏」里最高的那个与所有「值」里最低的那个之间；只有「亏」时，时间值至少抬到「亏」里最高的那个 |
| 嫌贵没成交 + 客户预算 | 客户上限（按学生 / 玩具 / 商单分开） | 同类客户预算的中位数；不动你的时间值 |

因为时间值按实际小时算，「亏」只反映价格不够，不会和「小时估少了」混在一起

### 你目前的情况会被纠正成什么（2026-11-04 口述）

- 接过的单做完全部觉得亏、没有一单觉得值 ⇒ 只有下限，时间值只会往上抬，不会往下降
- 大多数单客户嫌贵没成交 ⇒ 客户上限普遍低于你的底线，即可成交区间不存在
- 两条合在一起的结论：**问题不在你报得贵，而在接了本不该接的价**。系统的做法是：底线高于客户上限时，直接显示「这单在这个预算下不成立」，给出能成立的最小范围；不再给出低于底线的价格让你去接
- 起步数据：把过去接过 / 没接成的单按上面格式补录几条（大概价格、大概小时、亏没亏、客户说的预算），校准立刻有依据，不用等新单
