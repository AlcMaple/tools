# 017 - 网页版推荐与点评助手

> 2026-10-06 收口。09-01 已实现主体，09-04 补流式/生产问题，09-12 调整公开展示；不再保留成“尚待实施”的全套计划。[原计划](archive/017-网页版推荐与点评助手-实施计划.md)只供追溯。本轮未重跑 AI 或生产验收。

## 已落地的用户流程

`在看/看完卡片 → 选观后点评或推荐文 → 进度/语气/长度/剧透范围 → 4～6 道选择题（可手写补充）→ AI 初稿流式出现 → 用户编辑 → 保存草稿 / 发布 / 复制 / 下载海报`

- 进入助手不自动调用 AI；写作结果先可编辑，发布由用户操作，不由模型代发。
- 每账号、每番、每模式一份草稿和一份当前内容；点评/推荐独立，不互相覆盖。发布清掉临时问答草稿；撤回保留正文，不再公开。
- 公开需要“账号 `tracksPublic` + 内容已发布”两个条件；草稿、问题、答案不进大厅。当前大厅展示默认文章等后续行为，不按最早原型恢复。
- AI 不可用仍能手写、保存、发布和出海报；封面失败使用占位图。两模式同时存在的番剧分享图优先点评，下载不是发布。

## 数据与调用边界

- `review_drafts` / `review_contents` 是 Web 自有数据，不混进桌面 `tracks.extra`，不参与追番 `tracks_rev`；用户备份另按导出/导入规则处理。
- 服务器 AI 与 BYOK 是不同请求路径。点评 BYOK 为浏览器直连；**实际 key 在本机 localStorage，不是原计划的仅会话保存**，不进入服务端数据库或跨设备同步。Agent 的 BYOK 是另一模块，别混用存储/确认规则。
- AI 材料限定当前番资料和本次用户感受；BGM 获取失败可能退化为追番标题，不把少量资料包装成已知完整剧情。
- 实现入口：`web/server/reviews.ts`、`web/server/ai.ts`、`web/src/lib/sse.ts`；公开展示在 `web/server/community.ts`。模型、额度按运行配置，不把历史型号/价格写成外部平台现状。

## 已踩坑与剩余确认

- SSE 消费器曾被通用 `lib/` 忽略规则挡住：本地成功不等于干净 checkout 成功；新增源文件必须跟踪。
- 生产 Nginx 会攒流，响应要关闭代理缓冲；流式失败保留已生成内容，避免用户丢稿。海报 blob 预览受 CSP 约束，下载成功不代表预览成功。
- 海报评分使用有明确口径的用户信号，不把未评分项当零分；生成后核对标题、正文、评分、标签和公开范围。
- **待复核的实现差距**：当前 `ai.ts` 流式路径仍有 429/5xx 后的重连/续写逻辑，与项目“不对 HTTP 错误自动重试”的规范不一致；不要因文档归档就宣称已统一。请求次数/费用和重复片段应纳入下一次定向回归。
- **待复核的产品差距**：BYOK key 持久在浏览器与原“仅会话”目标不同；本轮如实记录，不擅自改代码或清除用户配置。
- 下次修改至少回归：两模式独立、跨设备草稿、撤回/关闭公开立即隐藏、AI 失败可手写、断流内容保留、海报和生产反代。历史构建通过不替代这些行为验收。
