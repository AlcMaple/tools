# 013 - 邮箱快捷注册与登录

> 开始：2026-08-08

## 结论

1. 浏览器自动填充、密码管理器保存的邮箱只是输入便利，不能证明用户当前控制这个邮箱；因此不能拿「浏览器里已经有邮箱」跳过首次验证。
2. 邮箱快捷入口采用「一次性验证码」：新邮箱输入验证码后设置密码；已存在且已验证的邮箱输入验证码后直接登录；之后也支持「邮箱 + 密码」普通登录。验证码单次、10 分钟过期、最多 5 次错误、按 IP / 邮箱限流，旧验证码重发后失效。
3. 邮箱是弱凭据，不等同于强 MFA。敏感操作仍应要求现有密码或未来的 Passkey；邮箱未配置时，原有用户名 / 密码注册登录不能被影响。
4. Google 登录暂不和本次 SMTP 功能混在一起。接入时必须由服务端验证 Google ID Token 的签名、`aud`、`iss`、`exp`，以不可变的 `sub` 作为外部身份键；`email_verified` 只能说明 Google 对该地址的验证状态，不能把前端传来的 email 当作身份主键。实现还需要 Google Web Client ID、授权域名和部署环境配置。
5. 本次不会把邮箱自动绑定到已有的用户名账号：已有邮箱凭据的账号可以直接登录，旧用户名账号继续使用原登录方式；如需绑定，应另做「登录态 + 当前密码 + 邮箱验证码」的显式设置流程，避免误合并账号。

## 数据与流程

```text
邮箱 ── start ──→ email_challenge（HMAC(code)、10 min、attempts）
  │                         │
  │                         └─ verify ──→ 已有 email → 签发本站会话
  │                                      新 email → 设置密码 → users.email_verified_at
  └──────────────────────────────────────→ 后续可 email + password 登录
```

验证码邮件通过 SMTP 发送。开发环境默认只在服务端控制台输出验证码；生产必须设置 `EMAIL_MODE=smtp`、`SMTP_HOST`、`SMTP_FROM` 等环境变量，缺失时只停用邮箱入口，不影响原有账号体系。
