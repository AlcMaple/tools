# 用户反馈

## 2026-09-28：站内反馈与回复

采用站内提交、站内回复，邮箱只负责通知；不建群、不新增悬浮球、不接入 AI 客服。

- 桌面网页侧栏底部、手机设置提供入口；搜索错误、播放器错误、助手错误和登录弹窗可直接反馈。独立入口 `/#/feedback` 支持未登录访问。
- 只要求填写正文；类型三选一，邮箱选填。最多 3 张截图，每张最终不超过 1 MB；浏览器缩放并重新编码。技术信息可查看、可取消，只收页面位置、平台、版本和错误代码，不包含 URL 查询参数、Cookie、聊天或完整日志。
- 登录用户按账号隔离，匿名用户按随机 httpOnly Cookie 隔离；匿名记录不自动合并进登录账号。图片读取也检查所属反馈权限。
- 我的反馈支持继续补充、未读提示；管理入口回复、更新「待处理 / 处理中 / 已解决」。用户补充后重新进入待处理。
- 正文、截图、待投递通知同一 SQLite 事务保存。通知失败仍返回提交成功，管理页显示失败并支持手动重发；不自动重复发邮件。已发送的通知不会重复投递；进程中断留下的 sending 状态需先核对投递结果。
- 管理员只允许明确配置的用户 ID 或已验证邮箱。新功能仅登记为助手可讲解的入口，不向助手开放反馈内容、截图、联系邮箱或管理工具。

配置：

```dotenv
FEEDBACK_ADMIN_EMAIL=<管理员已验证邮箱>
FEEDBACK_NOTIFY_TO=<新反馈通知邮箱>
# 可选：额外明确授权的用户 ID，逗号分隔
FEEDBACK_ADMIN_USER_IDS=
```

生产还需现有 SMTP 配置（SMTP_HOST / SMTP_FROM 等），设置在部署目录外的环境文件并重启；本轮只配置本地 `.env.local`，未修改生产环境。开发 console 模式只记录通知，不实际外发邮件。

接口统一在 `/api/feedback`：提交和列表、详情、图片、回复、已读、处理状态及管理通知重发。附件与反馈同库，备份整个持久数据库即可一起保存；用户的追番导出不包含反馈。

验收：临时数据库的自动化覆盖提交/附件权限、匿名/账号/管理员隔离、已验证邮箱授权、重复提交/回复、未读、状态、CSRF、限流、体积限制，以及 SMTP 拒绝连接后反馈仍完整保存。移除所属用户校验后对应断言失败。浏览器完成匿名提交 → 管理员查看/回复/更新状态 → 匿名用户查看回复；390 px 宽无横向溢出，登录错误也可打开反馈。

剩余确认：真实生产 SMTP 到达收件箱尚未验证；浏览器扩展未开启文件访问权限，自动化文件选择被阻止，截图上传 API 已测，手动选择/粘贴截图需用户验收。未提交、推送或部署。
