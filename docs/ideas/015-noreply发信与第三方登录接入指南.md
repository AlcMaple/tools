# 015 - 发信与第三方登录维护

> 2026-10-06 收口。保留日常排查所需配置与结论；平台注册截图、套餐比较和早期操作步骤已[归档](archive/015-发信与第三方登录-早期接入调研.md)。平台控制台、价格和密钥有效期会变，本轮未联网复核，不当作现行承诺。

## 邮件

- 历史选用 Brevo，经 SMTP 发验证码，不接另一套云邮件 SDK；`noreply` 是发件身份，不要求对应真实收件箱，但要完成域名授权，不能拿个人邮箱冒充域名。
- SPF/DKIM/DMARC 的记录类型、名称和值以实际发信控制台为准；送达须看投递结果及收件箱，不以“SMTP 接受”代替。历史曾出现部分邮箱可达而 Outlook 拒收，域名认证后改善。
- 配置入口：`EMAIL_MODE=smtp`、`SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURE`、`SMTP_USER`、`SMTP_PASS`、`SMTP_FROM`、`SMTP_FROM_NAME`。生产放部署目录外；dev console 仅用于本地调试。
- `SMTP_USER` 取 SMTP 控制台登录名，密码用 SMTP 凭据，不用 API v3 key；旧文示例密钥前缀互相矛盾，不据前缀猜类型。端口/TLS 配置与服务商一致。
- 长期不用后发送失败，先看凭据是否过期/撤销、域名状态、限额与投递日志；不要反复点发送放大限流。保留准确错误和人工重试，不把失败伪装成空结果。

## 第三方登录

| 入口 | 当前维护结论 |
|---|---|
| Google | 实现已在；配置 `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`。回调 `/api/auth/oauth/google/callback`。旧绑定方案已变化，身份边界见 [013](013-邮箱快捷注册与登录.md) |
| GitHub | 实现已在；配置 `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`。回调 `/api/auth/oauth/github/callback`。09-12 记录未做真实授权；不能从有按钮推断生产已配好 |
| Linux DO | 当前代码另有提供方绑定路径；配置及现行契约以 `web/server/oauth.ts` / `web/README.md` 为准，本轮未做真实授权验收 |
| Microsoft / Apple / QQ | 旧文是候选调研，不是已交付待启用功能；是否新增另行决定。缺某个第三方按钮不阻止对应邮箱走验证码 |

- 回调主机和协议必须与该环境实际地址匹配；开发和生产分别登记，不能把示例 localhost 端口当固定线上配置。
- 两项凭据缺一时入口应隐藏；用户取消授权不等于服务异常，真实失败按阶段处理。服务端使用短效票据与回跳限制，不把 access token 发给前端或持久记录。
- 旧指南的“Google → Microsoft → QQ → Apple”只是当时建议，已经被实际实现顺序取代，不再作为排期。
- 日常先查环境变量是否加载、入口开关、回调与投递日志；只有重建外部应用/域名或追溯历史故障时才翻归档。任何密钥修改与部署都需独立操作和验收。
