# BGM 登录功能（2026）

> 2026-10-06 阶段归档：06～07 月登录建设与修复已完成记录收口。[原始提交日志](archive/2026-BGM登录功能-06至07月.md)保留代码与实测细节；本页只留后续维护必须知道的结论，不代表本轮重新真登录验收。

## 完成结果与关键决策

- 桌面 BGM API token 与网页登录 cookie 是两套凭据：token 服务 API，cookie 服务网页搜索；不能拿其中一个的状态代替另一个。
- 登录窗捕获到关键 cookie 还不等于窗口外可用；曾因过早关窗存下半成品。等待落地导航及尾部 Set-Cookie，再用窗口外请求验证。
- **登录 UA 与搜索 UA 必须一致**。随机匿名 UA 与登录 cookie 混搭曾造成“界面已登录、搜索仍匿名”；sec-ch-ua 与平台提示也从同一 UA 来源对齐，不散落维护版本号。
- 校验只有正常响应才判断登录态；502/限流/网络异常保留原状态，不把缺少退出链接直接判过期。明确退出/失效同时清凭据和登录分区，避免残留 cookie 制造秒关窗假登录循环。
- 登录/验证状态在设置和查询入口同步；自动校验按逻辑日节流，手动校验单独处理，避免切 tab 就请求。
- 错误分类只认 CF 挑战强特征，不用裸 `server=cloudflare`；上游 5xx 与人机挑战分开提示。
- 原历史“匿名约 16 秒、登录约 0.6 秒”只说明当时差异，不承诺今天的性能。

## 接手检查

入口在 `src/main/bgm/credentials.ts`、`search.ts`、共享 UA 常量及渲染端 BGM 登录状态组件。改登录流程至少验：成功后窗口外复用、cookie/UA 一致、非 200 不清登录、显式退出清分区、重新登录不死循环。本文没有新增待开发功能；需要改行为时再补新的提交记录。
