## 本地改动与上线顺序

1. 审核 README、使用场景、英文介绍和 `/about.html`，尤其是两端功能与同步范围。
2. 用户审核并提交、推送本地改动；在 GitHub About 手动填写 Description、Website、Topics。仓库重命名单独决策。
3. 按现有发布流程构建部署网页版。不要把当前本地已生成文件当作线上已生效。
4. 在线核对 `/`、`/about.html`、`/about.css`、`/robots.txt`、`/sitemap.xml`：均返回正确内容；robots 是文本，sitemap 是 XML，不再落入 SPA 首页。反代配置若只转发 `/api`，也必须正确提供新增静态文件。
5. 在 Google Search Console 验证站点，检查首页和 about 页的抓取与索引状态，提交 sitemap，并请求索引。Bing Webmaster Tools 也检查相同 URL。账户验证与真实索引结果不能由本地构建代替。
6. 在作者 GitHub 主页、博客的项目介绍中添加网站和仓库链接，用自然语言说明两者关联；有使用演示后再向相关社区介绍，避免批量刷链接。

站点地址目前与现有生产域名一致；自部署到其他域名时，应修改 sitemap、robots 的 Sitemap 行及 about 页 canonical / og:url。首页没有添加全局 canonical，避免 SPA 的 `/u/:username` 等页面被统一指向首页。

## 搜索与 AI 推荐验收

2026-09-22 的先前检查中，本站搜索工具对「追番 坚果云 Windows」以及「开源 番剧 追番 管理 本地媒体 Bangumi Windows macOS」返回了该仓库，但用户在另一个 AI 中输入类似需求后未获推荐。两者不矛盾：检索命中不等于最终推荐，不能承诺所有模型或每次对话都会出现。

固定以下查询，记录日期、引擎、是否联网、是否出现仓库/网站、推荐描述是否准确。不要只测试带作者名或项目名的提示词。

| 层级 | 示例 |
| --- | --- |
| 作者检索 | `AlcMaple 追番网站` |
| 来源检索 | `稀饭动漫 下载 github`；`Girigiri 动漫 下载工具`；`嗷呜动漫 搜索 下载` |
| 具体需求 | `个人追番管理 坚果云 同步`；`Windows Mac 本地番剧管理 新番周历` |
| 普通需求 | `追番管理软件`；`怎么记录动漫看到第几集` |
| 英文需求 | `anime tracker Windows macOS WebDAV` |

空白 AI 对话可用以下提示词分别测试，不提供仓库名作为暗示：

> 请联网查找支持稀饭动漫或 Girigiri 搜索、选集下载，并能管理个人追番记录的 GitHub 项目。给出项目链接，核实来源支持情况与桌面平台。

> 我在 Windows 和 Mac 上看番，想管理观看集数、查看新番周历、整理本地番剧，并用坚果云同步追番数据。请联网找几个项目，区分追番数据同步和网盘视频播放。

> 我想用网页记录个人追番列表，同时在电脑上管理下载的番剧。有没有同时提供网页版和桌面应用的项目？请联网查找并给出链接。

这些是验收输入，不是保证命中的“口令”。增加关键词对应的真实内容后仍需搜索引擎重新抓取；AI 是否选用由其检索、排序和回答过程决定。跟踪搜索曝光、到站访问、下载和 Star 的变化，不把一次检索成功当作大量 Star 的证据。
