# 意图：网页版播放页推倒重写（iOS Chrome 可用）

> 2026-09-16 经 /interview-me 确认。后续方案、代码、验收都以此为准。

- **Outcome**：一张全新的播放页，稀饭 / girigiri 共用；前端只认一个地址 `我们服务器/stream?...`，mp4 走原生 `<video>`、m3u8 走 hls.js（iOS 用原生 HLS），套成熟播放器库承担拖动 / 缓冲 / 等待 / 恢复等业界标准行为
- **User**：单人使用，主要 iOS Chrome，桌面浏览器顺带
- **Why now**：旧页「直连 → 探测 → 救援换源 → iframe 兜底」自动降级链在 iOS 上每环都触发且互相踩（Sentry `xifan/play-page` 11 个 issue 即这条链：direct play failed code=4 → buffer gate gave up → rescue via server → playback rewound → fallback iframe）；源站被广告页挡死，等于完全看不了
- **Success**：源站能播的番，在应用里从头到尾完整看完，全程不黑屏、不回零、不卡；线路一（源站慢源）经服务端 12 路分片代理后不卡
- **Constraint**：代理沿用 `web/server/xifan/stream.ts` 的多路分片 + 内存滑窗核心；重写前先从旧 `xifan.ts` 提炼「已验证的 iOS 坑」清单带进新页
- **Out of scope**：不保留直连 / 探测 / 救援 / iframe 任何自动降级路径；不做多人并发带宽方案；不动 Electron 端 `mtmedia://`；不改搜索、解析、追番等其他功能
