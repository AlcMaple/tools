# MapleTools 更新失败：安装程序提示"无法关闭"/"Failed to uninstall old application files"

## 背景

用户反馈：更新 MapleTools 到新版本时，安装程序卡在"正在安装"，弹窗提示：

> MapleTools 无法关闭。请手动关闭它，然后单击重试以继续。

点"取消"后进一步报错：

> Failed to uninstall old application files. Please try running the installer again.: 2

这是 NSIS 安装包（electron-builder）在**覆盖安装前尝试卸载旧版本**时，发现 `MapleTools.exe` 仍在运行，无法删除/覆盖旧的可执行文件导致的。**不是安装包损坏，也不是版本问题**，是旧进程没有真正退出。

MapleTools 本身有"关闭到托盘"的设计（`src/main/index.ts`）：点窗口的 × 默认只是隐藏窗口、进程继续在后台/系统托盘运行。用户如果通过任务栏关闭窗口而不是真正退出，再点安装包更新，旧进程仍占用着 exe 文件，安装程序自然报错。

## 环境前提

- 以下命令在 **Windows 的 PowerShell** 或 **cmd** 均可执行，已注明差异。
- 关闭进程、结束任务不需要管理员权限；如任务管理器里看不到，需要"显示所有用户的进程"（有些版本需要管理员权限勾选）。

- [ ] 打开任务管理器（`Ctrl+Shift+Esc`），切到"详细信息"标签，找 `MapleTools.exe`
- [ ] 同时检查系统托盘（任务栏右下角、"显示隐藏的图标"箭头里）是否还有 MapleTools 的图标

- 没有 → 跳到第 3 步

- [ ] 结束进程/退出托盘图标后，重新双击安装包，看是否能正常走完安装

### 3. 如果任务管理器里看不到进程，但安装仍然报错

可能是文件被杀毒软件（火绒/360/QQ管家等）临时锁定扫描，或者安装包本身在写入时被拦截。

- [ ] 用 `tasklist` 命令再确认一次，比图形界面更准确：
```bat
tasklist | findstr /i mapletools
```
有输出 = 进程确实还在，记下 PID 后用 `taskkill /PID <PID> /F` 强制结束；无输出 = 进程层面已经没有了，问题在别处

- [ ] 检查杀毒软件是否有拦截记录/隔离记录（火绒："安全防护"→"查看日志"；360："全部日志"）

```

```

### 4. 兜底方案：手动卸载后全新安装

如果反复报错，可以先手动卸载旧版本、清干净残留后再装新的：

- [ ] 「设置」→「应用」→ 找到 MapleTools →"卸载"（走 Windows 标准卸载流程，不是覆盖安装）
- [ ] 卸载完成后，检查安装目录是否还有残留文件夹（默认通常在 `%LOCALAPPDATA%\Programs\MapleTools` 或用户选择的自定义路径），**如果有残留，先记下路径发回来确认，不要自己直接删**，避免误删到用户数据目录（`userData`，里面有下载记录、账号 cookie 等）
- [ ] 确认残留只是安装目录下的程序文件（不是 `番剧`/`下载` 等用户数据）后再删除
- [ ] 重新运行最新安装包做全新安装

## 根源修复（2026-08-12）

已在 [`build/installer.nsh`](../../build/installer.nsh) 加了 NSIS `preInit` 钩子：安装包启动的**最早期**（早于 electron-builder 自带的"进程占用检测"）静默执行 `taskkill /F /IM MapleTools.exe /T`，把还挂在后台/托盘的旧进程连子进程一起结束掉，这样后续的运行中检测就不会再触发，用户不会再看到"无法关闭"弹窗。

并在 `package.json` 的 `build.nsis` 里加了 `"include": "build/installer.nsh"` 接入这个钩子。

**注意**：这个改动只影响**安装包本身的行为**，只有下次打包发布（`npm run dist` / `npm run build:win`）产出的新安装包才带这个逻辑；用户手上这次的旧安装包不受影响，仍需按上面的步骤手动处理一次。
